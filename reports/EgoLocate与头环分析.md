# EgoLocate、头环与双目模组：如何接入训练主线

分析日期：2026-09-29。用户确认头环主要用于手部标定、精确控制和 SLAM。本文基于所给压缩包的静态文档/源码查看，以及相机规格 PDF 相关页渲染核对；没有执行压缩包中的程序或重新测量设备。

## 1. 资料中实际有些什么

`EgoLocate_副本.zip` 约 716 MB，共 1,585 个 ZIP 条目。只提取了规划所需文档与源码。双目资料含相机规格书、Linux/Windows SDK、头文件、示例及二进制。供核验的节选合计约 1.45 MB，位置和逐文件 SHA-256 见 [excerpt_manifest.json](../data/manifests/reference_excerpts_20260929.json)。压缩包中的历史运行说明作为项目资料阅读，不作为本次连接设备或运行代码的指令。

## 2. 头环在系统中承担三个不同任务

```text
衣服 IMU → FGP → 身体姿态、腕部初始估计、根运动信息
                         ↓
相机图像 → MediaPipe → HaMeR → 手部视觉观测 + 局部手指姿态
                         ↓
              坐标标定 / 时间对齐 / 可靠性筛选
                         ↓
         确定性上肢 IK 或 Stage-A 融合 → 身体/手部参考

相机图像 + 人体运动先验 → EgoLocate SLAM + 滤波 → 根轨迹信息

身体/手部/根运动参考 → 机器人重定向或策略参考编码
                    → 全身控制 + 末端控制 → 机器人
```

手腕 SE(3) 位姿、手指局部姿态与人体全局位移需要分别定义误差和验收标准。现有 24 关节 SMPL 身体表示不能直接表达完整手指；代码另用 MANO 和 SMPL-H 承载手指姿态。

## 3. 已有实现可以复用，但不能混成同一项能力

| 模块 | 从静态资料确认的内容 | 对当前任务的意义 |
| --- | --- | --- |
| `camera_backend.py` | RTSP 读帧；另一 UVC 路径把双目画面裁成单眼；有内参缩放及时间记录 | 现有路径主要提供单目图像，双目深度需要新增处理 |
| `egocentric_hand_recovery.py` | MediaPipe 手框/关键点与 HaMeR 手部恢复 | 复用感知，不从零训练手部网络 |
| `async_hand_recovery.py` | 默认 10 FPS 的有界手部工作线程，队列容量 1 | 身体和视觉手部更新频率不同，应研究观测年龄；满队列时丢弃新提交，不能据此称永远只处理最新帧 |
| `upper_limb_visual_ik.py` 与设计文档 | 基于视觉手腕观测、身体先验与时间门控的确定性融合路线 | 作为必要基线，设计文档不等于所有精度指标已通过 |
| `stage_a_fusion.py` | 30 帧因果窗口、两层 GRU、观测新鲜度门控与 FGP fallback | 已有学习式融合，不能把“加入 GRU”或“视觉加衣服”本身当成新贡献 |
| `smplh_mesh_recovery.py` | 身体与局部手指旋转组合为 SMPL-H | 可用于显示/参考生成，仍需机器人手的重定向 |
| `egolocate.py` | 人体运动先验、视觉 SLAM 与 Kalman 滤波融合根平移 | SLAM 估计人体/相机运动，不直接替机器人完成接触平衡 |

Stage-A 推理结构在包中，但引用的外部 `/Project/fuse` 训练工程与 `best.pth` 未在该 ZIP 中找到。因此现有资料支持“存在推理实现”，不支持“已经拿到完整 Stage-A 训练闭环”。同样，通用 torch 训练辅助函数不是完整机器人 PPO 配方。

Stage-A 当前代码的 `CORRECTED_JOINTS` 是排除 8 个下肢关节后的所有 SMPL 关节，包含 root、躯干、头和双臂；它并非设计文档所描述的单侧局部 IK。进入机器人前必须记录实际被修改的关节，分别比较两个 backend。

## 4. 需要优先测量的五个问题

1. **手指姿态与手腕位置精度分开。** 当前 Stage-A 手部特征主要使用 `global_orient` 构造旋转残差；这不证明腕部的度量位置已准确。HaMeR 的单目恢复也不能天然作为厘米级真值。
2. **真正的图像采集时刻尚需核验。** RTSP 路径在主机读帧之后调用 `time.monotonic()`；手部 worker 会继续携带这个时间，但它不等于相机曝光时刻。相机编码、传输、缓存的时间需单独测量。
3. **动态头部运动与固定外参。** 必须明确标定的是 camera-to-head 还是 camera-to-body-root。头会相对身体转动，固定 root-camera 旋转是否覆盖目标动作需要实测，不能仅在 T-pose 中通过。
4. **滤波时间步长。** `egolocate.py` 的 Kalman 模型使用 `dt=1/60`，文档实时链路目标约 30 FPS。要核查实际调用率与时间约定是否匹配；这是待验证的接口一致性问题，还不是已经证实的失稳根因。
5. **SLAM 重定位跳变。** 当前代码在特定大残差条件下直接修改滤波位置状态。人体显示可接受的地图修正不一定可直接成为机器人根目标；要测试连续控制参考的处理。

这些问题先通过固定录制、同步观测和离线回放测量，不同时改感知、融合和控制策略。

## 5. 双目硬件的能力与尚缺的一步

规格书第 3 页注明 USB 3.0、Global shutter、MJPEG/YUYV，标称组合图像模式包含 4000×1200 @ 60 FPS MJPEG 与 4000×1200 @ 30 FPS YUV；第 4 页列出 UVC 系统兼容性并给出双镜头结构图。以上是厂商标称，尚未实测。

资料存在需核验的一致性项：文件名含 `3261`，封面/图纸写 `3361`；单传感器有效像素表与组合输出宽度也不能据表格直接推定每眼裁剪范围。SDK 有软/硬件触发 API 与示例，但 API 存在不能证明该模组当前固件已实现所需双眼同步精度。

新增双目路线依次是：

1. 核实实物型号、左右图像布局、实际输出模式、曝光和同步误差。
2. 标定两眼内参、畸变和外参，校正图像，并通过已知尺寸目标验证度量尺度。
3. 在双眼都可见的手腕/手部特征上建立匹配并三角化；对遮挡、低视差、错误匹配拒绝输出。
4. 将度量手部观测与 HaMeR 局部手指先验融合，再转换到机器人参考坐标。
5. 若要双目 SLAM，额外实现/接入接受同步左右图像的 SLAM 通路；当前单眼 wrapper 不会自动利用双目信息。

由双目获得深度可以减少单目尺度歧义，但不会自动消除标定误差、运动模糊、遮挡与同步误差。

## 6. 更贴合项目的科研候选

**首选：异步视觉/衣服融合下，手部精度与全身稳定性的协同。**

最小任务先设为站立状态下的腕部到达/轨迹跟踪，测试可见、遮挡、快速转头、左右手交叉和视觉延迟。把纯 FGP、现有确定性 IK、可复现的 Stage-A、简单时间补偿与新方法放在同一控制器和同一预算下对比。

潜在方法是根据观测年龄/置信度和机器人接触状态调整末端参考权重；也可把这些信息输入策略，训练其在视觉失效时利用历史控制。前者实现较小，后者必须先有完整训练基线。要通过文献与实验判断新意，不提前承诺论文贡献。

指标必须包含机器人末端真实误差、触达成功率、全身姿态/接触稳定性以及引入的延迟。不能只看 SMPL-H 网格更平滑或融合网络自身的残差。

**备选：双目约束提升度量腕部定位。** 先验证同步/标定，再比较单目先验、双目三角化和融合；简单更换相机通常是工程改进，要有特定难点、方法及跨场景泛化证据才构成研究。

**后续：遥操参考驱动的机器人抓取学习。** 在末端和接触控制稳定后，可以采集示范做行为克隆，再用 RL 改善接触任务。视觉人体重建、全身运动 policy、手部操作 policy 是不同训练对象，应分别立项。
