# 第一课：SMPL 后面，机器人怎样动起来，策略又怎样学会控制

目标：读完能解释一次控制循环和一次训练更新。今天先把输入、输出与反馈搞清楚，不要求记住整个 PPO 推导。

## 1. 用抬手动作理解系统

你抬起右手，衣服和 FGP 估计出人体姿态，SMPL 表达这一姿态。机器人手臂长度、关节轴、可动范围与你不同，所以要把人体动作变成控制器能理解的参考。

参考可以是目标关节角、身体部位的位置和朝向，也可以是人体动作的编码。具体形式由策略训练时的接口决定。

机器人执行动作时还需要知道自身关节位置、速度、机身朝向等反馈。相同的抬手参考，在身体正直和向前倾倒时需要不同的控制动作。因此控制器通常同时看参考和自身状态。

这就是闭环：根据实际发生的运动，继续调整下一步命令。

## 2. 最小的一次控制循环

以“策略输出关节位置偏移，底层 PD 产生力矩”为例。实际机器人也可能采用别的 action 定义，需要读代码确认。

```python
# 概念伪代码，不是机器人启动脚本
observation = build_observation(robot_feedback, motion_reference, history)
action = policy(observation)
joint_target = default_joint_pose + action_scale * action
torque = kp * (joint_target - joint_position) - kd * joint_velocity
next_state = physics_step(torque)
```

- `joint_position` 是机器人此刻实际关节角，通常用弧度。
- `joint_target` 是希望关节到达的位置，不等于已经到达的位置。
- `action_scale` 把网络输出换成控制量，不能脱离训练配置随意改变。
- `kp` 根据位置误差给出恢复作用；`kd` 根据速度提供阻尼。上式假设目标速度为零，是教学简化。
- 真实实现还涉及目标速度、前馈、执行器饱和、滤波和频率等约束。

例子：默认关节角为 0.1 rad，动作是 0.4，缩放是 0.5 rad/动作单位，则目标为 0.3 rad。若实际角度仍为 0.2 rad，控制器面对的误差是 0.1 rad。这个例子只说明量的关系，不是任何机器人可直接采用的参数。

把仿真的 `qpos` 每一帧直接改成目标，能让动画看起来正确，却绕过了力、惯性和接触。真正验证控制器要推进物理仿真，让关节在控制作用下到达目标。

## 3. 强化学习是在上述循环外增加“评分与更新”

训练时，策略在仿真里产生动作。环境推进物理过程，再根据跟踪、平衡等目标计算奖励。积累一批交互轨迹后，训练算法更新策略参数，然后继续采集。

```python
# PPO 训练结构的概念伪代码
for iteration in training_iterations:
    rollout = collect_with_current_policy()
    returns, advantages = estimate_returns_and_advantages(rollout)
    for minibatch in make_minibatches(rollout, returns, advantages):
        loss = ppo_loss(minibatch)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
    evaluate_and_save_if_needed()
```

普通 PPO 不要求对物理仿真求导。它通过动作概率和采集到的回报估计策略梯度。部署时通常只运行策略前向推理与控制循环，权重保持固定。

SMPL 动作可作为训练的参考目标；策略通过与物理环境交互学习如何跟随。这类动作跟踪方法可以同时包含模仿目标和强化学习，不是“有示范数据就只能用监督学习”。

## 4. 八个词，按你这个项目理解

| 词 | 具体含义 |
| --- | --- |
| observation，观测 | 控制器当前能拿到的信息：关节、机身姿态、参考动作及历史等 |
| state，状态 | 描述环境的完整信息；仿真可能知道真机难以测得的量，不能与观测完全等同 |
| action，动作 | 网络输出的控制量，可以是位置偏移、速度或力矩等 |
| reward，奖励 | 当前行为按任务目标得到的评分，不是人工标注的正确 action |
| return，回报 | 一段未来奖励的折扣累积，训练希望提升长期效果 |
| actor，策略网络 | 给定观测后生成动作；训练时常输出动作分布以便探索 |
| critic，价值网络 | 预测从当前信息出发能获得的回报，帮助评价动作效果 |
| advantage，优势 | 某次动作/轨迹的结果比价值基线好多少，用来指导策略更新 |

Critic 有时使用仅仿真可得的信息辅助训练，部署 actor 仍必须只使用真机能得到的信息。这个设计叫非对称 actor-critic；不是所有算法都采用。

## 5. PPO 到底约束了什么

记旧策略对已采样动作的概率密度为 `π_old(a|o)`，新策略对应值为 `π_θ(a|o)`，两者之比记为 `ρ`。PPO 的核心裁剪目标常写为：

```text
L_clip = mean(min(ρ × A, clip(ρ, 1−ε, 1+ε) × A))
```

策略更新希望最大化该目标。`A` 是估计的优势：结果比预期好时，倾向于增加相应动作概率；结果差时，倾向于减少。裁剪减少同一批数据上过大更新的激励；它不是对所有策略变化的严格硬约束，也不保证机器人稳定。

完整损失通常还包含价值网络误差与探索熵项，具体正负号取决于代码采用最大化目标还是最小化 loss。

第二步再学习 GAE：它把不同时间跨度的 TD 误差加权，用于估计优势，在偏差和方差间折中。先看懂 rollout、概率比、优势和反向传播，再推导 GAE 会更有上下文。

初学阶段先使用成熟 PPO 实现。能够追踪张量、解释每项损失、改变一个奖励并验证结果，比只背公式或重写优化器更接近项目目标。

## 6. 奖励为什么会让机器人学偏

动作跟踪奖励通常组合多个目标：跟踪参考、保持身体姿态、满足接触要求，并减少过大力矩和动作变化。各项权重与归一化尺度需要明确。

如果只奖励“不倒”，机器人可能选择尽量不动；只看关节跟踪误差，可能牺牲平衡；只看总奖励上升，也可能掩盖其中一项变差。所以评估要另外记录动作完成率、跟踪误差、足端滑移和失败条件。

停止奖励计算、动作片段结束、跌倒终止、训练时间上限是不同事件。特别是 time-limit truncation 与真正 terminal state 对价值估计的处理可能不同，读训练代码时要核对。
