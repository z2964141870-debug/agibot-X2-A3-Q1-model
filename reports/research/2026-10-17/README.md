## PredActor：从只看现成模型，走到能检查训练入口

**它解决的问题。** 以前能运行G1现成模型，却缺少公开的“训练数据从哪来、怎样训练自己的模型”入口。现在作者默认分支给出了这条链：

```text
G1动作参考 + 已训练好的RLTracker老师
    -> Isaac Lab中执行、记录状态与动作
    -> MotionCLIP为轨迹附上语义条件
    -> 在固定轨迹数据上训练PredActor
    -> 重载自己的checkpoint做MuJoCo评测
```

这里的行为克隆（BC），可以理解成“从老师留下的记录学习该怎样行动”。这一步接近你熟悉的监督训练：从数据中取一批、计算损失、反传更新策略，重复多个epoch；本次检查的BC入口不需要按PPO方式交替更新Actor/Critic。老师本身的训练是另一个阶段，不能因学生用BC就认为老师和机器人能力免费获得。

**实际新增了什么。** 对比昨日固定头与当前`38fceddf2ad8c474100b9fc109d158197838383a`：13个提交、129个变更文件。现有采集入口、数据标注工具、`train.py`、训练配置，以及用自己checkpoint和对应配置评测的说明。作者配方以152条G1参考、每条50段为**目标7,600段**，文本条件BC示例为50个epoch；这些是作者的配置，不是本项目训练结果。采集配置还有失败重试/长时间停滞退出，不能把目标数写成保证收齐。

**和你的项目有什么关系。** 对“微调、从头训练，还是别的办法”，它给出一条具体候选：先有目标机器人的可靠老师，再采集该机器人的状态—动作数据，训练一个新的学生策略。对A3，可在既有官方035基线合格后评估老师是否适合提供数据；对Q1，仍须先取得或训练可靠老师、准备自己的本体和动作合同。G1的29关节顺序、动作尺度和输入表示不能直接套给智元。

**证据与开源。** 核验了原摘要/提交历史、作者仓库完整412项目录元数据，以及固定提交16份文档/源码/配置，逐份检查API内容长度、Git blob与目录SHA。训练器相关段落可见DataLoader、损失反传和优化器更新；未审完全部源码或复现。仓库根许可证为MIT，第三方及数据许可另查。作者资产清单列出RLTracker、MotionCLIP、PDP051权重和152条动作；本次Hugging Face元数据请求超时，**只能确认作者清单，不能确认文件当前可下载、哈希正确或可运行**。

**主要限制。** 公开README仍将DAgger交互式数据聚合、机载部署和硬件控制列为待发布。MotionCLIP从头训练另标Experimental，需要G1重定向AMASS和BABEL标注；152条采集参考并非完整编码器训练集，不能据入口名字断言在已发布G1权重上微调。默认采集1000并行环境不是最低算力需求；未核验本项目机器的显存、内存或训练耗时，也不能因BC损失下降就断言机器人站得更稳。

**建议：基线完成后再试。** 现在只把“目标本体老师→轨迹→学生训练”的流程纳入理解与候选清单。将来真要评估时，先核实小批数据的关节/动作/时间合同，固定相同动作比较老师与学生的独立闭环结果；未优于老师或明显损失旧能力，就不升级路线。本次不安装、不训练，不改变当前035与工程暂停状态；不登记新研究假设。
