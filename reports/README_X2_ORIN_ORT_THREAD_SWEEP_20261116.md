# X2 Orin MorphMimic 线程数对照

## Done

在 SoC1 上保留共享 TCP REP，以 4、2、1、1、2、4 线程顺序各跑一轮。唯一配置变量为 MorphMimic CPU ONNX Runtime 的 intra-op 线程数，实际从 session 读回核对。每轮 600 个状态请求、359 个人体包，使用同一份 `orin_real_worn` 录制和固定合成反馈。每轮 589 个状态就绪，状态 RPC 分段逐次闭合。定时回放比较之外，另用同一 96 包固定虚拟时钟检查数值，三组的 149 个就绪窗口、原始动作和最终关节目标逐值相同。

| 指标，分别列两轮 | 4 线程 | 2 线程 | 1 线程 |
| --- | ---: | ---: | ---: |
| 状态往返 P95 | 12.89 / 12.85 ms | 12.04 / 12.11 ms | 13.13 / 13.03 ms |
| 状态最大往返 | 20.91 / 21.20 ms | 15.81 / 15.32 ms | 15.42 / 17.29 ms |
| 就绪状态 RPC 超过 20 ms | 3 / 1178 | 0 / 1178 | 0 / 1178 |
| ONNX 前向 P95 | 5.55 / 5.70 ms | 5.10 / 5.21 ms | 6.43 / 6.66 ms |
| 人体包往返 P95 | 7.79 / 8.87 ms | 7.43 / 7.80 ms | 8.95 / 8.62 ms |

2 线程在两轮都获得最低状态 P95，这次选作下一步联跑候选。状态超时 0/1178 的证据范围为本机台架回环和短时窗口。完整墙钟回放有少量参考可见性差异，配对 589 个共同就绪周期中，每对有 586–587 个参考槽时刻和原始最右支持相同。各轮连续目标跳变峰值仍约 30°，线程数优化只涉及计算时序。未运行真实 FGP 推理、BLE、物理或电机，未改部署。板端原件 `/tmp/x2-zmq-ort-sweep.g1bMVB/result.json` 与 Mac 核同 SHA-256。
