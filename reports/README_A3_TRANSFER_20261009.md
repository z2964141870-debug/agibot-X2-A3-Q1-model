## 目标与结论

用户询问能否把 sonic-transfer 方法与智元官方 A3 GitHub 结合，训练自己的遥操策略。

结论：方法可以借鉴；优先在官方 A3 环境中建立预训练权重基线和普通微调基线，再对照冻结部分 Actor、只训练少量适配参数的路线。直接 G1→A3 是另一项跨本体实验，不能把 X2 ONNX 直接装入 A3 就当成完成迁移。论文 / 项目提供的证据不是 A3 复现证据。

## 方法怎样结合

迁移方法不是只给 PPO 换奖励。它在站姿、符号和动作范围不同且骨架高度相近的身体之间构造解析 codec，把目标机器人观测转换到原策略输入，再把原策略输出转换到目标机器人动作；保留原策略权重，仅在动力学解码器 Linear 层加入 LoRA 增量，通过仿真中的在线强化学习适应目标身体。论文 §4.3 的训练重点是广覆盖阶段→加入少量目标动作的精修阶段，持续监测未见动作并按退化停止；不能将“逐步放开动作幅度”概括为该论文主训练配方。

在我们建议的 PPO 对照中，Actor 的新增增量参加策略更新，Critic 保持正常价值训练，其参数也计入训练预算；这是本项目实现建议，不从作者仅讨论策略适配参数的比例推断其完整 Critic 配方。冻结原 Actor 权重不代表整个系统性能不会退化：输入映射、增量、输出映射改变后，旧技能仍需重新评测。论文也报告外部动作集中的一些运动失败，不能只看一个平均分。

推荐的 A3 同平台路线：

```text
衣服 / SMPL
  → 坐标、时间与人体到 A3 参考处理（待核验实时条件）
  → A3 参考 + A3 实际状态
  → 官方 A3 预训练 Actor + 可选少量训练参数
  → A3 动作缩放 / PD / 官方执行器模型
  → 仿真结果与奖励
  → PPO 更新可训练 Actor 参数及 Critic
```

同一个 A3 身体已有匹配输入输出时，没有必要为了套论文额外造一套 G1 codec。借鉴的是少参数适配和课程思想；若坚持使用原始 G1 核心，才必须重新设计 G1↔A3 codec，并验证其信息损失与输出能力。

## 官方 A3 能提供什么，不能直接抄什么

1. 官方 035 训练环境是 29 主动关节 A3；被动足关节仅参与物理。已有 T–N、电机速度 / 功率、并联机构和踝限位约束，以及拟合被动足配置。保留这些作为共同物理基础；不把 X2 比例、增益、关节顺序或电机限值套过来。
2. 官方已经支持从 035 PT warm-start 微调，而不是只有从零训练。默认 `resume=false` 会重置训练状态，不能与恢复 E005 的完整 optimizer / counter 续训混淆。
3. 官方公开叶子是 `sonic_a3_035.yaml`，启用 `g1` / `a3_fast`，Actor 配置为 UniversalToken / MLP 编码解码网络。不要按“LLM 有 attention”预设插入点；应按实际 Linear 层和 forward / checkpoint / export 接口实现。
4. trainer 存在通用 `peft_config` 处理代码，但当前 A3 训练配置没有启用它；不能据此声称已有经过验证的一键 A3 LoRA。冻结范围、Critic 是否被误冻结、状态字典、优化器、辅助损失和 ONNX 导出都要验证。
5. `g1` / `g1_dyn` / `g1_kin` 名称部分属于 ABI 历史命名，不证明加载的是未经适配的 G1 策略。不能只按键名选择“冻结 G1 网络”。
6. A3-fast 配置需要 10 个间隔 20 ms 的参考帧，即 0–180 ms。对实时衣服输入，需要实测延迟、缓冲或预测；LoRA 本身不生成尚未采集的未来帧。配置中出现 SMPL 键不证明已加载可用 SMPL 权重 / 实时路径，须检查发布 PT 与实际激活模块。
7. X2 仓库部分回放配置冻结腕部；其身体跟踪示例不能直接证明满足头环精确手 / 腕遥操。未来必须单独评测腕部、躯干、腿部与支撑平衡。

## 推荐实验顺序

| 实验 | 初始化与更新范围 | 要回答的问题 |
| --- | --- | --- |
| B0 | 官方 A3 035 PT，保持策略不训练 | 本机同配置下基础跟踪是否成立？ |
| B1 | 同一 PT，官方普通微调 Actor / Critic | 默认公开路线能否适配我们的目标动作？ |
| B2 | 同一 PT，冻结选定 Actor 层，只更新明确登记的少量参数及 Critic | 同预算下是否保持跟踪 / 旧技能并减少训练成本？ |
| 可选跨本体 | 原始 G1 PT + 新 A3 codec + LoRA + A3 物理环境 | 跨本体迁移是否比已有 A3 起点更有价值？ |

当前 E005 从零训练实验单独保留，不能拿官方预训练的全部历史算力当成零成本，再直接宣称从零基线更差。B1 / B2 先只改变适配方式，动作采样与动作范围保持一致；若我们额外设计动作范围课程，其作用另做单变量对照，避免多个变量同时改变。这是实验建议，不是已复现论文的配方。

最小可行比较使用相同 035 PT、仿真配置、动作数据、训练步预算、采样种子和评测清单。可先按完整动作序列固定 16 个训练 / 4 个验证序列做工程试验，并登记名单；不能按相邻帧随机拆分。公开 selected20 只是启动样例，不是大规模动作覆盖；论文结论需增加未见动作 / 自己的录制及多种子，检查预训练数据重叠。

共同报告：动作完成率、跌倒 / 提前终止、身体与腕部误差、关节误差、电机限制触发、推理延迟、更新数、实际墙钟时间、GPU / RAM 峰值。所有路线重测原始动作以检查遗忘；固定条件评测与训练日志分开。论文的 GPU / 动作集 / 参数统计口径不同，不直接拿参数减少比例推算本机训练时间。作者项目页明确 novel500 / hard300v3 未使用显式 held-out 划分，而 PDF §3 对 novel500 有 held-out 描述；存在口径差异，不采用其分数作为本项目泛化结论，后续固定自己的划分并澄清差异。

进入 B2 前，至少完成零增量时输出等价、只更新预定参数而基座哈希不变、Critic 仍可更新、保存重载一致、导出后闭环回放等检查。若 LoRA 增量始终近零且无收益、固定容量末层微调已相当、训练成本没有降低或未见动作 / 跌倒变差，则降低其优先级。量化阈值在 B0 指标确定后、正式比较前固定，不编造提升目标。

这些是已有方法的复现 / 对照路线，尚不是创新。只有确定具体项目瓶颈并与朴素方法比较后，才讨论研究贡献；不把“LoRA + PPO + A3”本身称为原创。
