## 1. GAE：先把人体动作变成可学的参考，再处理真机与延迟

[原论文](https://arxiv.org/abs/2609.34233) · [作者项目页](https://wangyf0928.github.io/gae-wlrobotics/)

**做了什么：** 先训练一个能利用额外信息的仿真策略，生成机器人可执行的轨迹；再用这些轨迹监督部署策略，同时逐步增加环境变化。部署策略接收人体动作，另用延迟条件预测稍后的运动，减少“机器人总慢半拍”。作者在 G1 与 Westlake O1 上报告了真机遥操；O1 需要微调。

**对我们有什么用：** 它直接对应“人体参考 → 策略训练 → 遥操”的缺口。先看清参考质量与训练鲁棒性怎样分别处理，有助于理解为什么人体动作映射成功不等于策略就容易训练。这里的 GAE 是 *General Action Expert*，与 PPO 中同缩写的“广义优势估计”不是一个概念。

**证据与边界：** 已读摘要、正文的方法和延迟实验相关段落及项目页；未复现。在本次检查的项目页中未找到公开训练仓库入口，不能视作可直接使用的开源训练配方。正文将人体 token 的旋转位置编码按延迟偏移；更长预测时间也会增加跟踪误差，不能保证消除任意延迟，更未验证 X2/A3/Q1。

**建议：现在阅读方法，基线完成后再试。** 优先借鉴分阶段训练和延迟评测；“给策略加延迟条件或时间编码”已有直接先例，需纳入选题对照。

## 2. DexRoam：头戴双目采集到机器人训练，关键是三种对齐

[原论文](https://arxiv.org/abs/2609.35761) · [采集与对齐仓库](https://github.com/zhourui9813/DexRoam) · [训练仓库](https://github.com/zhourui9813/DexRoam-Policy-Training)

**做了什么：** 使用 Quest 3 与头戴 ZED Mini 采集人体示范，把人体和机器人在身体结构、动作含义、执行节奏上的差异分别处理，再把人体与机器人示范用于视觉语言动作模型训练。

**对我们有什么用：** 与头环、双目、手部控制很接近。可以参考它如何记录图像/身体/手部数据，以及如何把世界坐标中的动作变成机器人可学习的动作。它按任务进度重采样示范来适配执行节奏；这是离线训练数据对齐，不能当成实时传感器同步或网络延迟补偿。

**证据与边界：** 已读原摘要、正文硬件/时间处理段落、两个仓库 README、对齐说明和数据卡，未运行代码。实验平台是 **Astribot–XHand 移动操作机器人**，不是智元双足平台；也不是现成的 PPO 平衡训练配方。公开数据卡标明目前是 **50 段、单任务集成样例**，不是完整论文训练语料；数据、依赖和模型未下载，完整复现性与许可仍需逐项核验。

**建议：基线完成后再试，先保留数据格式参考。** 不因为它使用头戴设备就替换现有 FGP/EgoLocate。

## 3. HOI-Retarget：搬物体时，“碰到同一位置”比姿态相似更关键

[原论文](https://arxiv.org/abs/2609.34674) · [代码](https://github.com/shinben0327/hoi-retarget) · [数据卡](https://huggingface.co/datasets/shinben0327/hoi-retarget)

**做了什么：** 把人与物体接触的位置定义在物体坐标系中，再优化机器人轨迹，同时考虑脚部支撑、平滑性和关节限制。这样人和机器人身高不同、物体大小变化时，也能围绕接触关系生成参考。

**对我们有什么用：** 衣服生成 SMPL 身体动作之后，如果要搬箱子或扶物体，仅追踪身体姿态往往不够。该方法提醒我们还需要物体位姿、形状和接触信息。

**证据与边界：** 已核对原摘要、项目页、仓库 README、入口配置、许可证和数据卡；未运行。其输入包含 **SMPL-X、物体轨迹和接触标注**，现有 SMPL 身体输出不能直接替代全部输入。公开轨迹覆盖 G1/H2；这是一套参考生成方法，不等于已获得智元全身控制策略，也不保证运动学优化后的参考能被真机稳定执行。代码为 BSD-3-Clause，数据卡为 CC BY-NC-SA 4.0，SMPL-X 等源资产另有条件。

**建议：接触操作阶段再试。** 当前先完成无物体的基础跟踪训练。
