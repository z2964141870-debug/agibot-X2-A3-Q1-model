## 当前代码已确认的事实

- `script/supermimic_for_q1/supermimic/envs/mdp/rewards.py`同时包含全局根位置/朝向、身体位置/朝向/线速度/角速度、动作变化及限位项。不是只有站立/存活奖励，也不是漏掉全局根位置。
- 身体位置/朝向先按机器人根的xy/yaw重对齐；全局漂移另由根位置项约束。默认根位置权重0.5，正奖励权重总和5，占理论正奖励上限10%。该比例是代码结构，不是本轮实际分项收益或因果消融结果。
- 根位置项为`dt * 0.5 * exp(-squared_position_error / 0.3**2)`。由公式可推知离参考很远时，该项值及其局部状态梯度可能很弱；不据此断言它是本轮不走路的唯一原因，也不直接修改论文路线的奖励权重。
- `world_model/world_model.py`训练8步自回归状态误差与终止分类，当前日志的第8步状态误差没有直接衡量动作Jacobian或真实收益梯度的质量。`imagination/policy_trainer.py`实际通过冻结模型/critic对actor做BPTT。
- `contact_protocol.py`的已登记修正是提高脚碰撞几何的priority，让接触摩擦采用脚/回合配置；这个修正不能证明重定向接触相位、足底无滑动或模型梯度已正确。没有在本次读取服务器XML或测量接触刚度，不猜测当前软接触参数是否合适。
- `q1_assets.py`还登记了Q1适配的PD50/2、模型额定力矩25%上限。这属于后续参考动力学可行性需一并考虑的执行条件，未证明上限不足，不因本次讨论改控制参数。

## 关键判断与下一条诊断

三者可能沿同一链条相互影响：参考落脚/根运动不协调，使真实接触与参考不符；模型在接触附近给出偏差动作响应；策略再沿偏差方向提高想象奖励。稠密奖励增加约束，但错误参考或不可靠响应仍会破坏这条链。MuJoCo软接触与网络平滑可降低优化困难，不能保证梯度处处正确，也不能推导出接触应调得越软越好。

优先在本轮已有固定8条训练参考和保存轨迹上区分三类证据，保留原奖励和模型：

1. 按原解析公式重算真实轨迹的奖励分项，量化高回报来自哪里，以及根位置/速度项是否有有效信号。
2. 将同一参考的左右脚高度、世界系脚速和支撑切换，与实际策略轨迹的接触状态/法向力对应，区别参考不协调、执行接触不同与持续原地站立；必要时看力矩饱和。
3. 从完整可复现的相同MuJoCo初态和上下文出发，在抬脚、落脚和双支撑附近，比较模型动作方向导数与真实有限幅度扰动的回报/位移变化，报告H1/H8/H32、多个扰动尺度、方向和幅度。开环动作检查与闭环策略收益检查分开说明，不能把一个替代另一个；接触切换处有限差分随扰动尺度变化本身也是结果。

第3项最直接回答“模型建议朝这个方向改动作，真实仿真是否也获益”，而不是继续以低状态MSE证明策略梯度可靠。以上为下一步诊断安排，没有在本次实际执行；没有启动续训或更改任何输入/控制/奖励。
