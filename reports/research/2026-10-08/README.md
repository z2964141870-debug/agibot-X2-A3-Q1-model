## 1. Beyond Retargeting：把在线重定向省到训练阶段

[论文](https://arxiv.org/abs/2610.07891v1)先用重定向动作和 PPO 训练教师，再教一个直接读取人体动作与机器人自身状态的学生策略。学生把嘈杂、缺失的人体观测映射到学过的动作原型，再输出关节目标。

**与我们有关：**可以作为“SMPL→在线重定向→跟踪策略”的未来对照，但“免重定向”只针对部署；训练仍需重定向示范。动作原型是合理补全，不保证恢复的就是操作者真实意图，特别是新动作或手部精细控制。

延迟要分开读：作者报告 RTX 4060 上算法路径为 **0.604 ms**；选定 5 秒打拳片段的视频测量中，包含感知、传输与机械响应的中位延迟为 **147.5 ms**。前者不能代表整条遥操链路，后者也不是全场景延迟保证。

**建议：人形跟踪基线完成后再试。**原文未提供本次能核验的官方实现/权重入口；已读方法、噪声与部分输入实验、延迟测量和结论，未核验代码。其动作码本逐帧处理，长期结构仍是作者列出的不足。

## 2. BRACE：拿着东西上坡时，跟踪目标也要调整

[论文](https://arxiv.org/abs/2610.07052v1)处理操作者站平地、机器人却在坡上推拉物体的差异：先按地形、手部受力和身体支撑关系改造训练参考，分别训练“主动施力”和“抵抗外力”的教师，再合成一个部署策略。

**与我们有关：**衣服动作准确不代表机器人在负载和不同地面上也能照做。它提示我们，参考动作本身可能需要调整，否则“完全模仿原动作”和“受力后保持稳定”的奖励会相互冲突。

部署策略不读取高度图或实测外力，但仍需要动作目标、模式与力指令，并用自身关节/惯性观测历史推断环境影响。**“不用力传感器”不等于“不需要给力目标”。**论文训练用了约 6.5 万条参考和 8 张 RTX Pro 6000，完整复现不是当前入门任务。

**建议：基线完成后再试。**已读相关方法、评测和[作者项目页](https://multiplylabs.github.io/brace/)，尚未核验到完整训练代码、权重与资产下载入口。已有 G1 实验；定量比较主要针对动作/负载跟踪器，尚未与力指令控制器做同口径力精度比较，不能据此宣称全面领先。

## 3. BiGym 2.0：先让评测能公平重来

[论文](https://arxiv.org/abs/2610.07594v1)提供一个围绕 G1 家务操作的仿真基准。最值得我们现在记住的是：**恢复机器人姿态，还不够恢复一次实验。**控制器历史、内部状态也要恢复，才能让同样的初始条件产生可比较的轨迹。

它还使用独立评测种子，避免每次都挑评测分数最高的 checkpoint 来证明进步。我们后续做奖励对照、人形跟踪时，可借鉴“固定评测协议、统一底层控制器、保留完整状态”的做法。

**建议：现在借鉴评测设计，暂不换环境。**已选读任务接口、评测协议和局限，未复现。全部结果是仿真；任务策略之下已有冻结的全身控制器，不能当作从零训练底层平衡策略的教程。作者称环境和示范已开源，但给出的[仓库](https://github.com/swirl-uk/BiGym2)三个 API 入口本次均返回 404，网页连接也未成功，实际代码、数据、许可证和权重可用性未确认。

## 4. 更正 OCLO：双手之外，仍有行走指令

[作者项目页](https://oclo-humanoid.github.io/)相较昨天发生了实质澄清：输入是“双手目标＋行走速度”，真机用 G1 摇杆给行走指令；自动生成的是骨盆高度和躯干姿态。昨天“只指定双手目标”的概括不完整，已在[原简报](../2026-10-07/README.md)加上更正。

这意味着，头环提供手腕目标之外，我们仍需定义行走意图的输入。**现在修正接口理解；实现仍等基线完成。**本次核验项目页差异；arXiv v1 摘要/正文与昨天缓存相同，没有确认新论文版本，也没有新增代码或实验发布证据。项目页未给修订时间，只能把 10/8 记为发现日期。
