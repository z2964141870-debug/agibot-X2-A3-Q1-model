### 3. 机器人模型核验

- 22 个可动关节：腿部每侧6，手臂每侧4，腰部2。标准 URDF 的手腕与头部是固定关节，即使某些固定关节附带 limit，也不能算作可控自由度。
- 标准 URDF 累计质量16.917298 kg；带足底点版本16.997298 kg。MuJoCo 版本约16.917288 kg。它们是文件参数，不是实测称重；不能混用不同资产身份。
- 6 份资产的网格引用全部在压缩包内找到，没有缺失 mesh。
- `q1_v3.xml` 和 `q1_v3_full_range.xml` 各有22关节和浮动基座，但没有 actuator/sensor 段；单独加载不能作为已经可以控制/训练的环境。
- `q1_v3_mc.xml` 有22个 motor、浮动基座、地面及49个传感器定义，是优先检查的仿真候选。XML 定义中的 IMU 只是仿真传感器，不能证明 SDK 暴露了真机 IMU。
- `q1_v3_no_collision.urdf` 仍保留1个 pelvis 碰撞体；不能只凭文件名判断碰撞配置。`with_points` 增加足底结构和质量，需明确用途后选用。

**关键不一致：SDK 文档关节限位/力矩与模型不相符。** 例如左膝在文档1090–1114行是[-0.4887,0.4887] rad、33 N·m，而标准URDF是[0,2.4435] rad、36 N·m；腰roll在文档是[0,3.142]，模型是[-0.2618,0.2618]。模型肩/肘多处为22 N·m，文档为14/33 N·m。不能自行判定哪份正确、也不能单纯取交集当成可部署参数；可能涉及型号、版本、零位或文档错配，需要厂家/真机配置确认。

## 关键决定及理由

1. 最终目标保留为全身实时动作跟随。现有上肢控制可供单独调试，但不作为主路线替代品。
2. 先确认厂家是否另有实时全身参考接口或可二开跟踪器。现有SDK证据不足，不能宣称机器人绝对没有该能力；如另有接口且确认输入、时序和固件匹配，可复用官方控制器。
3. 若没有满足条件的现成跟踪器，则采用“SMPL标准化 → Q1全身重定向 → 动作跟踪policy → 板端低层控制”。底层接口已经存在，因此问题是缺少合用的跟踪控制器及其反馈契约，不是完全没有机器人接口。
4. 类似SONIC指采用人体参考驱动、结合机器人状态保持动力学可执行的跟踪策略；现有G1/X2模型不能因输入也叫SMPL而直接用于Q1。Q1自由度、质量、尺度、动作顺序与电机能力均需重新适配，通常需要训练/微调。

## 目标数据链与开发阶段

```text
动捕SMPL帧 + 原始时间戳
  -> 字段/坐标系/尺度标准化，处理丢帧和延迟
  -> SMPL人体运动 -> Q1 22关节参考 + 根运动/足接触约束
  -> 跟踪策略(reference, q, dq, base orientation, angular velocity, history)
  -> 22关节目标（策略动作语义由训练配置定义）
  -> 板端伺服插值/PD/时序检查
  -> /aima/hal/joint/command
  <- /aima/hal/joint/state + 尚待确认的真机IMU/基座反馈
```

SMPL 的 `poses` 通常表示人体关节局部旋转，`betas` 表示体型，`trans` 表示根平移；这只是常见约定，不能假设设备一定采用72维轴角或输出平移。人体姿态不是电机命令：骨架尺度、关节轴与可控自由度不同，还要处理脚接触、落脚位置和动力学平衡。
