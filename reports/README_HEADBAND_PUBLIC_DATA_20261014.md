用户确认头环没有连接、没有新数据。继续做无需实物的公开数据与算法准备，不能把缺失观测补成“已开始训练”。已有HB01/HB02的协议与旧录制结论保留，不重复研究。

下一工作收窄为两层：首先量化视觉根运动能补足多少人体轨迹；随后证明这份信息能改变机器人实际控制条件，才试冻结035下的参考修正。候选贡献仍是按控制结果区分参考误差方向的代价；头环+IMU融合、根补偿、置信度加权本身均有先例，不能宣称原创或已优于035。

## 控制器必须能用到新增信息

读取既有[E27已保存结果](README_A3_SMPL_ROOT_AUDIT_20261013.md)，没有复跑：499帧根X额外0.2m/s、终点+1.992m时，保持关节q/v、根朝向及机器人历史，实际1570维输入差仍0；关节/yaw正对照有效。E27已经证明独立根目标不在当前A3-fast直接输入中，而不是证明模型不能走路。

由此修正HB03前置条件：只把头环结果写入root字段，不能期望相同输入的确定性策略改变动作。必须明确用可行的足/关节参考将根运动编码进当前通道，或者另开显式根命令适配分支。第一路线仍需新IK/闭环证据；第二路线已是新增接口与训练变量，不能继续称完全原接口冻结对照。先测输入、量化token和动作是否感知该扰动，再测方向敏感度和控制效果。不重复E27已完成的纯根反事实。

这也是“感知更准但机器人没改善”的可检验解释之一，尚未证明它造成既有跌倒。

原文首次2026-04-08，沿HB01已核验论文，不再泛查。此次新增核验作者[项目页](https://roshi-mocap.github.io/)、[评测说明](https://roshi-mocap.github.io/documentation/pipeline/evaluation.html)及[作者仓库](https://github.com/Jirl-upenn/RoSHI-MoCap)。2026-10-14读取API得到提交`f3c9b2338233b38ea0be6af5846f1e1dbcd14674`，提交时间2026-07-31T22:12:57Z。网站声称的发布规模与本次实际下载分开记录。
