## 原论文实际如何使用数据

论文4.1与附录E：主实验训练库是公开G1重定向的BONES-SEED，过滤后129,514段、264.56小时，是SONIC数据的公开子集；不是本文证明为PHUMA单库或LAFAN/Motion-X/PHUMA合并的库。另一个受控实验使用LAFAN1的40段/2.45小时（Fig.4）。当前PHUMA作为用户指定的替代训练原料，复现的是训练方法，数据来源并未与论文主实验完全对齐。不能把40段理解为40个几秒钟小片。

正文3.1/4.2：使用一个共享策略和一个共享世界模型覆盖动作库，策略以期望运动为条件；不同动作共享机器人刚体/接触动力学。Fig.3及附录F.3的规模实验分别用1/7/40/264小时子集，观察到模型八步预测误差大致稳定、达到目标回报的算力增长较慢。该结果支持扩动作覆盖，但不是所有指标随数据数量单调变好的证明。

附录D.1：以1秒为bin，以bin为单位重置；50%均匀分布、40%当前低回报softmax分布、10%历史累计分布。均匀项确保覆盖，困难项多练低回报时段，历史项保留对曾经困难动作的练习。原文确认动作噪声、观测噪声及物理参数随机化；本次未找到本版明确要求reset pose/velocity noise的参数，不将本地未开该噪声说成已确认的协议违例。

正文3.1/3.2：人体/机器人参考提供跟随目标；世界模型的监督来自在线高保真仿真产生的状态-动作-下一状态，滚动进入FIFO buffer，不把动捕姿态直接当作动力学转移。想象训练初始状态从真实交互buffer采样，再由世界模型展开、回报和critic指导策略。这是参考多样性与在线交互覆盖两条数据链。

附录D.2/Table A.5：50Hz控制、每GPU4096环境、每环境buffer1000步、世界模型每次更新10批且每批2048个八步窗口、策略batch4096个想象展开、默认H32、总320000轮；250000是学习率余弦衰减长度，不是总训练长度。不能拿共享3090的97.7分钟与论文H100的约3小时按墙钟等同工作量。4096x320000约13.11亿环境转移是完整表中配置的算术量级，不是本项目实测，亦不能直接当作达到3h里程碑时的交互计数。

附录E/Table A.7：142220个原始BONES-SEED动作先按名称去掉楼梯、箱子、椅子等交互需求，去12553段；再做几何可行性过滤，去153段，最终129514段。三类几何条件是最低身体link高度超过0.20m持续至少0.6s；低于-0.12m或低于-0.08m占比超80%的穿地；以及身体近静止、骨盆直立且在站高时，双脚精确碰撞几何距地均超过0.02m持续至少0.5s。最后一项特意用静止条件排除正常抛物线跳跃。阈值按G1/50Hz标定，不能直接复制给Q1。由片数算得保留约91.07%，不是90%帧足底15mm内的条件；也不能与不同源/机器人/重定向通过率作公平质量排名。

附录F.1/F.2另明确：129514段主基准是训练集动作，失败数衡量训练库覆盖，不是未见动作泛化。当前要验证Q1未见移动能力，仍需独立留出的移动评测，不能把作者训练集覆盖与本项目test混为一个指标。

## 与当前实现的具体差距

| 项目 | 论文 | 当前PHUMA R01 |
| --- | --- | --- |
| 一般策略参考 | 129514段/264.56h | 11训练chunk/41.30s，2移动 |
| 小库对照 | LAFAN-1 40段/2.45h | 只达到通路验证级参考规模 |
| 参考时域 | 动作序列按一秒分桶 | PHUMA包内已切短chunk，多数120帧@30Hz、约3.97s |
| 重置采样 | 1s、50/40/10混合 | 已实现同类1s和50/40/10混合，并非缺少该机制 |
| 真实交互 | 4096环境/320k轮表中配置 | 16环境/3000轮，共48000转移 |
| buffer | 每环境1000步 | 每环境1000步；总容量因环境数少而小 |
| actor / WM batch | 4096 / 每批2048窗口 | 128 / 每批64窗口 |
| 参考准入 | 名称交互过滤、架高/穿地/静止双脚悬空 | 19门，含90%帧脚底<=15mm、最大间隙30mm、2rad/s速度等 |

41.30秒相对论文LAFAN-1对照时长少约214倍，相对BONES-SEED主库少约2.3万倍；这比11段与40段的数量差更有意义。不能把重复训练41秒参考的次数增加，当作增加独立动作覆盖。文件已有73076个也不表示已经训练73076个。当前test没有移动片，不能宣称未见移动泛化。

源码另明确首轮候选配额是train80/development16/test16，总计112片；全库扫描之后没有持续补足被拒绝的候选，独立19门最终只留下11/4/3片。因此当前量少既有试跑配额原因，也有保守Q1参考准入的原因，并非PHUMA原料只剩18片。下一版应按实际合格时长和类别覆盖分批补足，而不沿用112片停止点。

现有代码证据：`supermimic/envs/mdp/motion_library.py`默认`bin_frames=50`，`q1_sim.py:reset`具有50/40/10混合及低回报softmax；`train.py`buffer为`num_envs x 1000`、默认H32。当前Q1库还拒绝compact/packed模式，扩到小时级前需实测参考内存并准备分块加载，不能直接把全库塞入GPU。上述均未在本次修改冻结代码。

## 决定与下一实验路线

1. 将R01准确归类为小规模训练闭环。先暂停扩展时域/模型诊断，建立独立PHUMA P04扩量版本；旧R01及19门结果不追改。
2. 在已固定train/development来源组内分批扩候选，覆盖移动、转向、下蹲、上肢和组合动作。先达到30分钟工程里程碑，再争取至少1小时合格训练参考；1小时是本项目选用的下一阶段目标，也对应论文规模消融的最小点，论文未将其定义为通用最低要求。不是已完成数据量或保证成功的阈值。数量、有效秒数、来源组、动作类别和拒绝原因均登记。
3. 对齐论文语义，独立比较本项目保守贴地门与适用于Q1的异常/持续漂浮过滤。D02C已证明原源穿地波动及目标映射都会影响固定落地后支撑比例；不能直接删门放行，也不把身体最低点和脚底混为同一变量。用训练/开发固定样本验证接触、自碰撞和匹配动力学，保留坏样本及原结果后再确定新准入协议。
4. 检查短chunk边界/来源连续性，保持原速50Hz，防止拼接错动作；实现可恢复批处理和适配内存的参考加载。先保证数据真实可用，再扩大在线交互buffer覆盖与预算，保持世界模型/critic/H32路线。
5. 采用嵌套的小库/扩量库，冻结同一开发评测；按相同环境转移预算比较，额外报告真实算力开销。测试集含移动的独立新协议须在选型前固定，旧test结果保留，不能用旧test来挑重定向/训练参数。

数据量不足是已确认的复现规模差距，值得优先纠正，但不是已证明的唯一失败原因。11片中的移动本身尚未学好，因此扩量不能替代小库可学习性检查。更多动作会提高学习难度，不承诺只靠扩数据就让Q1走稳；还需正确Q1参考、充分交互、可靠世界模型和独立移动评测。当前保留论文默认H32，将小库与扩量库放在匹配转移预算下比较，不同时更改时域、奖励和数据来解释因果。
