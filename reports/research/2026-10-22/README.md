## 1. FRDV：先检查动作是否可执行，再拿它训练

[论文](https://arxiv.org/html/2610.28470v1)题为《Fast Motion Retargeting Pipeline for Scalable Humanoid Robot Learning》。它先快速把人体动作变为满足关节/碰撞约束的机器人姿态，再对困难动作**选择性地做动力学优化**，检查电机力矩、脚与地面的接触能否支持跟随，修正滑脚、悬脚；没有有效优化轨迹的参考不进入下游训练。

与你的衣服→SMPL→A3/Q1直接相关：机器人跟不住时，要把参考本身不可行与策略能力不足分开。可先借这个问题组织已有证据，算法等基线完成后再试。优化器能跟随也不保证我们的policy或真机能跟随。

**证据/资产/限制：** 摘要、方法/实验/限制相关正文和[作者页](https://daroslab.github.io/frdv/)已核，未核实现或权重。作者报告的9,156帧/秒是20个CPU进程、关闭边界细化的**纯运动学吞吐，不含动力学校验**；分块还可能产生不连续。作者页明确代码coming soon，计划只公开运动学部分，**不含动力学校验**。G1/Dash结果不能当A3/Q1通过。建议：**现在借鉴诊断，基线完成后再试方法。**

## 2. 多视角动作预训练：第二个互补视角可能比堆数据更有用

《[Multi-View Latent Action Pretraining for Cross-Embodiment Robot Learning from Videos](https://arxiv.org/html/2610.27794v1)》先让同步多相机共同判断运动，再压缩成动作表示。直观地说，一个画面难区分手向前伸还是向侧面动，另一个角度能补上深度和遮挡信息，再用于跨机器人学习。

对头环的启发是先检查缺的是哪种观测：衣服、头环、外部视角能否互相补足，而不是直接加记忆或扩大模型。**这是操纵任务的证据，不是头环SLAM或人形平衡方案。** 作者的预训练视角静止、同步；移动头环的外参和时钟仍需单独解决。未来帧用于离线训练监督，不代表实时遥操可偷看未来；下游使用外部相机加腕部相机，也不是单摄像头部署。

**证据/资产/限制：** 相关正文/实验及[作者页](https://learnsyslab.github.io/multiview_latent_action_pretraining/)已核；已查页面未找到公开代码/权重入口，不能推断全网没有。仍需目标机器人带动作标签的数据；没有核验A3/Q1成本。建议：**基线完成后再试，先明确观测与对时条件。**

首稿：2026-10-20 07:55:43 UTC／北京时间15:55:43。

## 3. PointHand：操作者看到什么，会影响采集到什么

《[What Novice Operators See Changes What the Policy Learns](https://arxiv.org/html/2610.27907v1)》把操作者画面中的完整机器人手改为关键点，突出拇指/食指和接近物体的提示，以减少遮挡。它提醒我们：头环遥操除了估计手腕，还要让人看清机器人与物体的位置关系，演示质量也会受界面影响。

**证据/资产/限制：** 作者报告18名新手加4名专家的仿真研究；相关方法/实验/限制及[作者页](https://omron-sinicx.github.io/point-hand/)已核，未核代码或复现。显示给人的图像与policy输入分开；策略对比同时改变观测和编码器，不能归因为“只加关键点”。物体定位使用仿真真值构造理想检测框，作者将相关收益视为上限；五个seed只改变抽到的演示，网络初始化固定。一个手部任务不证明真实头环叠加显示有效，页面未找到代码/数据/权重入口。建议：**基线完成后再考虑界面与示教对照。**
