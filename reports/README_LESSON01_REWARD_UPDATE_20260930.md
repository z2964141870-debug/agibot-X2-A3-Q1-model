## 核心解释

**reward 是评分规则，参数更新是策略从经验中调整自己的过程。**

例如让手臂靠近目标：更接近时得正奖励，更远时得负奖励。这个规则告诉训练算法我们重视什么；仅算出奖励，策略并不会自动改变。

| 要判断的问题 | 应该看什么 |
| --- | --- |
| 希望机器人学成什么？ | reward 是否表达任务要求；例如跟踪目标、保持平衡、动作平顺 |
| 这次训练有没有改动策略？ | 是否执行优化更新，并比较更新前后实际参数；仅有更新调用也可能因零梯度或零学习率没有变化 |
| 改完真的更好吗？ | 在相同评估条件下比较任务指标；随机任务还要多次评估，不能只看一次 reward |

reward 很重要，也需要合适的观测、动作定义、交互数据、优化算法和训练设置。reward 变高可以来自初始状态更简单、随机性或评分规则变化；参数变了也不保证任务能力提高。

在本节的普通 PyTorch 用法中：

```python
loss = ...                  # 训练算法根据采集的数据构造优化目标
optimizer.zero_grad()       # 清除上一次梯度
loss.backward()             # 算出参数应怎样调整的信号，还没有改参数
optimizer.step()            # 根据梯度与学习率更新参数
```

固定策略在评估中也可以计算和记录 reward。`backward()` 不能和 `step()` 混为一谈。本实验没有额外参数修改、运行统计量或自定义更新钩子。

## 完成内容与关键决定

新增 [reward_vs_update.py](../script/teaching/lesson01/reward_vs_update.py)，使用单步策略梯度 REINFORCE，而不是 PPO。这样可以真的通过交互奖励更新策略，同时只保留理解本节必需的部分。

- 玩具状态：角度 10°，目标 30°。这是数值游戏，没有力矩、PD、惯性或接触。
- 观测为常数 `[1]`，仅表示这一种固定情景，不学习对不同状态的泛化。
- 两个离散动作：角度 −1° 或 +1°；执行一次动作就结束一回合。
- 奖励 = 动作前的距离 − 动作后的距离。因此两种动作分别得到 −1、+1。
- 策略是一个无偏置线性层，两个可训练参数均从 0 开始，通过 softmax 得到两个动作的概率。
- 收集 64 个独立单步回合，固定随机种子 7；用 SGD、学习率 0.1 做一次更新。
- 由于一回合只有一步，累计回报等于本步 reward。使用 `loss = -(log_prob * reward.detach()).mean()`；梯度经过动作概率计算，不穿过环境奖励。

**这里的一步例子不能推广为“机器人每得到一个即时奖励就立即改一次参数”。** PPO 通常先采集一批轨迹，再根据回报、优势等构造损失，更新策略和价值网络；机器人某次动作的好坏还可能取决于之后是否失去平衡。本节不要求记住这些公式。

下一小步继续使用单关节抬手的**假设数值**，不是新增仿真实测：

| 环节 | 本例内容 | 含义 |
| --- | --- | --- |
| 观测 observation | 参考角 30°、实际角 10°、角速度 0 | 决策时网络能获得的信息，包含任务参考与机器人反馈 |
| 策略 policy | 根据观测计算控制命令 | 可训练的决策规则；本例用神经网络表示 |
| 动作 action | 下达关节目标 15° | 教学中把物理单位的目标角作为动作；它不是参考角 30°，也不是实际角 |
| 环境 environment | PD 产生力矩、仿真推进动力学 | 执行命令后发生什么；本例的环境边界包含 PD 与物理过程 |
| 下一次观测 | 假设实际角到 12°，同时取得新速度 | 执行后的反馈；12° 是说明用的假设，不能由目标 15° 直接推算出来 |
| 奖励 reward | 距离从 20° 缩到 18°，本例记 +2 | 教学评分 `原误差 - 新误差`，根据实际运动结果计算 |

这个观测列表仅是示意，并不是已核验的 X2 actor 完整观测向量。真实输入常需要坐标约定、归一化及身体姿态等更多信息。已检查的 X2 接口实际使用 `joint_target = default_angle + action_scale * action`；上表为了先认清概念，省略了这层缩放映射。

本例奖励只用于解释评分位置；完整机器人任务还要处理跟踪、平衡、平滑性等要求，不能将此简单差分奖励直接当作 X2 训练配方。环境通常返回下一次观测、奖励和是否结束等信息。

训练时收集一批这样的交互，再由 PPO 构造损失并更新参数；部署时可以持续获取观测、输出动作而保持网络参数固定。reward 不必作为当前 actor 的直接输入；某些具体方法可以使用过去的奖励，本课暂不引入。
