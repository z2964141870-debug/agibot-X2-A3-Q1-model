## 1. SuperMimic：作者公开 G1 训练源码

[作者仓库的固定提交](https://github.com/HybridRobotics/supermimic/tree/5efbf114e11f725c31d83e217be987c13c0e4ce2)有两套 Unitree G1 任务：一套主要用根部和关节状态表示机器人，另一套用各身体部件的状态表示。训练先从物理仿真收集短轨迹，让世界模型学会连续预测；策略再在模型里试动作，用预测的跟踪奖励来改进动作。源码另有 PPO 入口。轮次不等于样本数：主循环按采样量决定更新次数，并分别记录采样、训练模型和训练策略的时间。

**现在做：读源码对照。** 对照 Q1 已有多步诊断，优先核状态坐标、动作缩放、奖励及终止条件，还有每次模型更新用了多少真实仿真转移。证据是作者组织仓库、固定树和训练入口静态核验；代码为 Apache-2.0。它依赖兄弟目录 `mjlab_research`，本次公开 API 为 404；未核实配套依赖、动作数据或可用的官方预训练权重。播放入口需要自己的 W&B run 路径；源码包未列 Q1 任务。仓库创建于 11/10 10:46:56 UTC，固定提交的 committer 时间为 11/10 16:10:56 UTC（北京时间 11/11 00:10:56）；11/11 核实公开，精确首次开放时间未知。旧 Demo 资产的许可不随代码改变。

## 3. 一步误差小，控制器仍可能选错动作

[Planners Exploit Deterministic Error](https://arxiv.org/html/2611.11780v1)把世界模型的中间计算压到低精度。作者发现，逐轮挑动作的规划器会反复偏向被同一个舍入误差“高估”的动作；每轮换一次舍入扰动，可减少这种偏向。这解释了为何一步状态预测看起来差不多，闭环任务表现却可能变差。

**现在做：借用评测口径。** 读 Q1 多步诊断时，把状态误差、奖励偏差和实际闭环表现分开解释；这篇没有证明 Q1 的梯度策略存在同一种误差，也不建议现在量化模型。证据为 v1 方法、对照和限制正文；实验是 TD-MPC2 / DINO-WM 的采样规划，没有真机。作者报告的 A40 低精度模型滚动比 FP32 快、但不及预转换权重的 BF16 路径；不代表整机遥操延迟。代码与设计文档写明待最终稿发布，未核验到本版资产。11/9 02:37:20 UTC 提交，11/10 公告。

## 4. RoboMoCap：给衣服和头环对时的一份离线参考

[RoboMoCap](https://arxiv.org/html/2611.10994v1)用头戴和腕部相机采视野，用外部光学动捕给遮挡中的身体和脚提供独立参考。作者用头戴陀螺仪与外部追踪的同一个头部动作找时间偏移，再估计时钟漂移，保留各传感器的原始时间戳。作者报告 200 多小时、1.2 万多个片段；G1 重定向只评运动学，没有验证真实接触、控制或跌倒。

**基线完成后再试：**把共同动作对时与独立腕、脚参考作为采集设计的参考。[作者项目页](https://bitrobot-foundation.github.io/robomocap/)和 [Hugging Face 数据卡](https://huggingface.co/datasets/BitRobot/robomocap)可见，卡片列 CC BY-NC 4.0；本机数据卡与树 API 超时，未下载或核验分片，评测代码未核验。正文用外部光学系统，不证明仅靠现有衣服与头环就可做到同等精度。11/7 22:27:20 UTC 提交（北京时间 11/8 06:27:20），11/10 公告。
