# 2026-11-23 具身智能研究简报

本期公开研究没有确认的新论文、仓库发行或方法版本。值得通知的是 Q1 远端在 11 月 22 日新增了 FGP Control V2 和策略训练交接，带来了第一批可核验的真机 FGP 运行数据与离线因果对照。

## Q1 FGP Control V2：链路已可测，下肢仍是训练瓶颈

最新 Q1 提交 `f871b80ce7538967789c1e12b3f226e2b11590ab` 的交接记录报告：FGP 有效帧 **6603**，均为 `tracking` 且 `realtime_valid=true`；FGP 推理延迟 P50/P95 为 **27.4/40.3 ms**，human_smpl policy 帧 **9828**，policy 看到的 FGP 年龄 P50/P95 为 **31.9/53.0 ms**，target 与真机关节误差 P50/P95 为 **0.207/0.474 rad**。这些数字来自项目保存的真机记录，本次只读核验，没有重跑。

同一段真机 FGP 记录的离线仿真因果对照更能定位问题：旧 adapter 的 CGFA 对照运行 12 秒后失稳，root 置零对照约 66.58 秒后失稳；A2 FGP V2 + CGFA 连续 **119.72 秒**完成，最大倾角 **13.50°**、target error P95 **0.515 rad**；A2 + MuJoCo 真值 root 反馈也完成，A2 + zeroed root 仍失稳。它支持“FGP 适配和根反馈是实际瓶颈”的工程判断，但不等于已经完成策略训练或真机安全验收。

现场退出时发生一次摔倒，交接记录把原因归为 `PASSIVE_DEFAULT` 不可用时旧退出流程发送 `stiffness=0, damping=5`；退出前倾角约 **3.4°**，因此该事故没有被计为 policy 失稳样本。Q1 当前保留 FGP 50 Hz paced FIFO、短断流宽限、Planner/human_smpl 热切换和同步采集器；原始大日志仍只在设备端，未纳入本次 Git 载荷。

## 对训练主线的影响

交接建议先冻结上肢，对同一 FGP 片段做输入提前/延后相位诊断，再为下肢补脚踝高度、足端速度、支撑/摆动相位和触地语义，并使用下肢专项损失。这里是工程训练计划，不登记为新的论文假设；当前不启动训练、不替换默认部署包，也不改变 SONIC kplanner 现场站立基线。建议“基线完成后再试”，先把上肢保持、下肢误差、相位和退出流程分开评测。
