# X2 FGP 逐帧标定与线程等待对照

## Done

共享输入链路是上下衣 BLE → 配对 IMU → T-pose 坐标标定 → FGP S1（CANO、LIP、GP/物理）→ 带时间戳的 SMPL 姿态和根平移。MorphMimic 接人体参考窗口和机器人反馈，输出关节目标。SONIC 走自己的 SMPL 转换、tokenizer 和 decoder，并有 kplanner 站立与 tracking 参考切换。两条分支都还需要处理参考变化、反馈、目标保护和控制权交接。

本次仅跑共享输入链路。复用已录 IMU 与标定参数，每组 96 帧、按 30 Hz 定时释放，原位、提前、提前、原位四个独立进程。两边都用两帧 FIFO，输出每组 67 帧，帧序一致。第二轮在两组内都固定推理调用线程 CPU 2、录制释放线程 CPU 3，分别记录逐帧标定墙钟、线程 CPU 时间、上下文切换和入队调用。其他线程和系统保持原配置。

| 指标 | 原位标定 | 提前标定 |
| --- | ---: | ---: |
| 第一轮输入释放至 SMPL 输出 P95 | 43.44 ms | 56.41 ms |
| 第二轮输入释放至 SMPL 输出 P95 | 45.42 ms | 49.82 ms |
| 第二轮标定墙钟 P95 | 1.01 ms | 8.57 ms |
| 第二轮标定线程 CPU P95 | 0.98 ms | 2.94 ms |
| 第二轮入队调用 P95 | 0.052 ms | 0.061 ms |
| 第二轮输出间隔超过 33.33 ms | 50 / 132 | 56 / 132 |

第二轮标定阶段的自愿上下文切换为原位 0、提前 11,878 次。标定墙钟减线程 CPU 时间的逐帧差值 P95 为 0.032 和 5.86 ms。结合入队调用耗时，可将本次候选的问题缩小到并发标定调用与部分帧进入推理前的等待，无法把等待精确归到 Python GIL、Torch 锁或系统调度。提前方案两次 P95 分别为 42.14 和 51.87 ms，尾部收益不稳定。跨配置最大姿态矩阵分量差 `3.58e-7`，根平移分量差 `8.94e-8 m`。输出一致性只评价同输入数值。

不采用提前标定。录制释放至输出耗时未含 BLE、策略和机械执行，现场测试继续暂停。Orin 实验锁已释放，已安装的 FGP、模型和控制脚本未改。
