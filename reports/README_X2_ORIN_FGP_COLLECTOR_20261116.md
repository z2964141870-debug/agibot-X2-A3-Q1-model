# X2 Orin FGP 独立结果接收

## Done

在原分阶段 S1 上增加可选的结果接收线程。CANO 仍由原线程提交，独立线程读取 CPU 进程的回包，并立即交给接收端。CPU 仍逐帧处理，最多一个请求未完成。重置会等待旧回包交付结束，因此旧回包不会跨过已完成的重置。下一次接入衣服时仍需在消费端按标定代次拒绝旧帧。

同机以主线程收取、独立线程、独立线程、主线程收取的次序，四轮各回放同一段 240 帧录制 IMU。每轮前 29 帧预热，输出 211 帧且源帧时标和顺序全匹配。两次独立线程实测接收线程均与 CANO 不同。姿态矩阵最大分量差 4.77e-7，根平移最大分量差 2.16e-7 m。每轮 CPU 子进程正常退出，预览锁释放。

| 指标，两轮分别列出 | 主线程取结果 | 独立线程取结果 |
| --- | ---: | ---: |
| CPU 算完到接收 P95 | 15.92 / 15.74 ms | 0.66 / 0.75 ms |
| 录制释放到接收 P95 | 50.89 / 50.12 ms | 39.53 / 40.37 ms |
| 出帧间隔 P95 | 51.90 / 51.31 ms | 40.77 / 42.19 ms |
| 最长出帧间隔 | 54.89 / 54.79 ms | 45.07 / 46.23 ms |
| 间隔超过 33.33 ms | 74 / 100（各 210 个间隔） | 104 / 105（各 210 个间隔） |
| 平均出帧率 | 29.987 / 29.997 Hz | 29.993 / 29.962 Hz |

长间隔缩短，但超过帧周期的次数未降，不能判断稳定 30 Hz。两轮独立接收共 420 个间隔，最慢 42 个中有 41 个以标定加 CANO 耗时的相邻帧增量为主要贡献。按轮分别看最慢 21 个，CANO 增量中位为 6.61 / 8.33 ms，标定为 +0.076 / −0.039 ms。本轮定位到 CANO 主机计时区间。历史 CUDA 事件提示需要区分流执行、D2H 和主机调度，现有结果无法判断具体 GPU 算子或单一原因。

本轮只使用 Orin 临时目录 `/home/run/x2-fgp-collector.QM5832`，真实衣服入口未切换。无新 BLE、机器人反馈订阅、MC 或电机输出，策略未参与。46 项 Mac 回归通过。板端正本 844 行逐帧计时仍在该目录的 `trace.jsonl`，SHA-256 `98ada9d5dca535ec37a51b45fdaac28b4e4fe3bd0a1c56d73e90676213681064`。
