# X2 人体输入与策略计算分离

## Done

在 Mac 用已录 FGP 人体包、固定合成 X2 反馈和原 ONNX 策略做四轮墙钟回放，串行、分开、分开、串行。每轮 180 个人体包、300 个 50 Hz 状态请求。串行方案在同一个执行队列处理人体入库与策略前向。分开方案独立派发人体入库和状态计算，只在修改人体缓存或抽取参考窗期间持同一把锁。人体到达时间在拿到锁、入库前记录，每个就绪参考窗的 10 槽最右支持时间都逐一校验，均早于或等于该状态请求的取窗截止。缓存新鲜度、插值缺口与模型参考窗沿用原运行时。

| 指标，分别列两轮 | 串行 | 人体入库独立 |
| --- | ---: | ---: |
| 人体包执行队列等待 P95 | 2.50 / 2.44 ms | 1.17 / 1.22 ms |
| 人体包计划发送至完成 P95 | 5.50 / 5.52 ms | 5.07 / 5.00 ms |
| 人体包计划发送至完成最大值 | 34.39 / 6.86 ms | 5.71 / 11.85 ms |
| 状态计划发送至完成 P95 | 7.16 / 7.36 ms | 7.19 / 7.31 ms |
| 策略就绪次数 | 289 / 289 | 290 / 289 |

按两组相邻实验配对，两边各有 289 个共同就绪周期，参考窗时间和最右支持完全相同的分别为 252 和 265 个。提前入库改变了部分推理周期可见的人体帧，周期相邻目标峰值在一组从 9.37° 到 10.30°，另一组均为 9.37°。该候选能减少本机队列等待，整条人体包路径的 P95 仅小幅改善，最大值在短样本中波动。参考窗口存在变化，后续需要验证其对动作的影响。

本轮不经过 ZMQ、真实 FGP 推理、BLE 或机器人执行。结果不代表 Orin 会有同等收益，尚未改部署，也未发送电机命令。真实设备上曾出现的共享 REP 等待仍需要独立回环对照。
