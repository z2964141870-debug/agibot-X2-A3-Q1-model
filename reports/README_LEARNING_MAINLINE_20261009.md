## A3 公开工程的来源判定

结论：这是智元官方 GitHub 组织 `AgibotTech` 下公开发布的 A3 适配工程。依据不只是组织名相似：智元自身网站的 Genie Sim 3.0 发布文章明确将开源资料链接到 `github.com/AgibotTech/genie_sim`，形成公司网站到同一 GitHub 组织的来源核验；A3 仓库处于该组织下且公开可读。

其 README 明确基于 NVIDIA `NVlabs/GR00T-WholeBodyControl` 的 SONIC 实现，保留上游研究组件，提供 A3 仿真、训练与部署适配。应分别归属“上游 SONIC 方法 / 实现”和“智元组织发布的 A3 适配”，不能把它写成我们独立发明的算法。

官方组织发布不等于已经通过我们手头型号、固件和衣服输入的验收。仓库自述为开发参考，且当前发行不包含 SMPL / teleop encoder，需在上游产生兼容的机器人参考。可训练权重、低层接口和具体硬件兼容仍按模型选型报告核验。

## 教学顺序与每阶段的做法

1. 先从一个关节的控制链开始，穿插必要 Python：观测如何进入 Actor、输出如何成为目标、PD 怎样执行、实际反馈怎样回来。第一项检查为本人画图并解释目标与反馈的区别。
2. 阅读一条人体 / 机器人动作样本，补张量、索引、关节、坐标和时间；逐项发现输入错误，暂不引入大规模数据集和复杂训练配方。
3. 结合已有可运行训练代码，找到采集、reward、Actor / Critic 更新、保存 / 重载；按当前理解补原理。已有倒立摆实验继续作为对照工具，不把它当作人形模型训练已通过。
4. 使用所选机器人路线的最小验证，学习统一评测和故障定位；比较固定条件下的实际控制表现，确认资源预算。具体运行是后续工程阶段，本轮没有启动。
5. 在可复现基线上只改一个主要变量，先写预期再比较，报告失败与波动；科研贡献在结果与先行工作核验后判断。

每个小节采用“具体例子或结果 -> 对应代码 / 配置 -> 本人一项操作或判断 -> 回顾”。每讲完约 2–3 个关键概念或出现卡点就做阶段总结，频率随反馈调整。围绕同一个例子串联参考、观测、动作、奖励、两个网络及参数更新，记录“已讲解 / 已答对 / 独立完成 / 仍需确认”。

数学按任务补齐：张量维度、加权平方误差、均值方差、梯度与学习率、基本坐标 / 旋转，处理姿态时再补四元数；暂不把完整 PPO / GAE 推导当作开始实践的门槛。若之后研究结论依赖新的优化规则或稳定性证明，再学对应理论。

Agent 协助查资料、写适配、检查代码和分析日志；本人亲自确认任务、物理含义、实验假设、结果与结论。每一阶段的产物应同时包含实际证据和本人说明，不能只有 Agent 给出的答案。
