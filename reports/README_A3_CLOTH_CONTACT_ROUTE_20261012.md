回答用户“不训练新编码器时下一步是什么、能否针对衣服特调、SONIC是否有双脚平衡、FGP缺根速度/接触是否造成迈不出步”。本轮只读原hp3090的固定官方源码、发布035匹配配置、Q1历史记录，以及Mac现存LFP运行源码。原机不恢复计算，不操作机器人，不改驱动/功率/BIOS。

用户长期目标仍是衣服驱动机器人完整运动，并在相同条件下取得相对官方权重的可验证提升。新人体编码器属于输入接口的一条候选路线，不是达到目标的前置条件。本问题是路线选择，不能自动解释为启动E22或学生训练。

## 核验结论

### 1. A3已经有闭环控制，但与人体接触估计是两层问题

固定官方vendor提交`fe6868ba37034f89b912f0fb851bce19f120266d`。`README.md`说明035面向基本行走/简单操作，只有G1与A3-fast编码器，没有SMPL/teleop编码器，仍需上游实时重定向；主要支持双脚接触或单脚抬起，不支持跪地、躺下、起身和未验证的高动态运动。被动脚建模用于近似足底柔顺、减轻踮脚，官方也说明其仿真不稳定和弯曲过大的局限。

实际035发布`config.yaml`的policy包含重力方向、基座角速度、关节角/速度、上次动作历史，未包含人体支撑脚标签或独立足底力观测。训练含根姿态/位置、身体位置/速度跟踪、动作变化、关节/踝电机约束和非期望碰撞奖励，以及姿态/足位置偏离终止。闭环网络利用机器人反馈学会全身协调和平衡，不能把它说成无平衡能力；也不能把训练contact sensor等同于部署Actor收到人体触地C。

核对的是实际035叶配置与发布resolved配置，而非通用`sonic_a3.yaml`中“3 encoders”的注释。当前035也没有选择另一个含`foot_end_load`的奖励组合；该文件存在不能证明本模型启用它。

### 2. 不能把“缺根速度”直接推成A3必然迈不出步

A3-fast实际参考是10帧、20ms间隔、0–180ms的29关节角/速度，以及参考相对机器人根朝向6D表示，合计640维。这个发布接口没有独立的世界根平移、人体根线速度或左右脚接触字段。完整机器人运动库仍需要一致的根姿态/轨迹来做重定向、仿真初始化和训练奖励，但不能擅自把额外字段塞入640维接口。

因此，缺根轨迹可能使上游形成原地、滑脚或矛盾的参考，属于优先排查假设；它不是“只要缺根速度A3就绝对不能走”的已证结论。周期腿部关节参考也可能引出步行，是否发生有效位移必须看实际闭环。还需区分被锁定的双脚、过小抬脚、关节/轴向错误、错误标定、延迟与控制器分布范围。

平衡也不等于双脚始终贴地。迈步需要允许摆动脚离地、支撑脚承担支撑并完成转换；长期锁住两脚会阻碍步行。人体接触估计必须经机器人形态与动力学检验，不能原样作为机器人必然可实现的接触计划。

### 3. 原始FGP与我们现有的FGP扩展不能混称

用户提供的原始FGP旋转输出描述与“姿态不能唯一确定全局运动”的判断合理。局部脚位置与速度不能直接当成世界脚位置与速度；完整关系还涉及根朝向旋转：

```text
p_world = t_root + R_root * p_local
v_world = v_root + dR_root/dt * p_local + R_root * dp_local/dt
```

但结合时序姿态、IMU、地面与支撑假设，可以估计接触/根运动；估计不等于测得真值，漂移和支撑误判须验收。

Q1已有FGP扩展的E003/E004保存了根位移、修正前后根速度、关节线/角速度、`foot_contact_probability [T,2]`与`velocity_valid`。身体输出的根位移并非零。现在的缺口是可靠性、坐标/时间对齐和独立验证，不是所有运行分支都完全没有这些字段。trace从源帧29开始、身体输出从源帧59开始，比较须按`frame_index`对齐。旧两段零位移JSONL用户确认本来没有移动，不能据此认定移动估计失败。

已有内部包标签对照的走路/单腿关节位置P95为37.75/39.35cm、根轨迹RMSE为65.79/53.61cm，支持先排查输入重建/根朝向/校准。这是既有内部标签比较，模型可能见过样本，不是独立动捕真值或泛化成绩；本阶段没有重跑。

### 4. LFP后处理可以复用，但要先明确实际运行分支

Mac现存`x2_pc1_ble_teleop/x2_mocap_gmr.py`选择`LFP_dense_taichi_ft.onnx`，默认`physics_optim=True`且`beta=None`。`DataProcessServer_FullBody.__init__`由此把`predict_result`绑定为`predict_result_optim_0911test`，调用`mos1.physics_models.KinematicModel(fps=30, bio_axis=True)`，以pose/vel更新并返回优化姿态和根平移。该模型使用人体运动学、接触点/支撑投影估计与根速度融合，不能当成机器人动力学平衡验收。

同类的未启用物理优化方法`predict_result`确有`vel[10]/vel[11]`脚速阈值接触估计、较慢脚FK位移与`vel[0]/30`根位移融合，但它不是当前入口的默认方法。`predict_VP_result_optim_new`又是另一条件分支。不能因为搜到同名方法就把所有后处理步骤描述成当前执行路径。

这些接触量仍是算法估计。冻结LFP ONNX和运行源码可用于离线对照，不需要先重训LFP；没有确认其原PyTorch网络/训练项目，不能承诺直接继续训练ONNX。此轮没有运行网络、安装依赖或修改现存遥操程序。

## 不训练新编码器时的建议顺序

1. **先拆上游人体参考。** 用同一现存走路段检查姿态、朝向、根位移和左右脚支撑转换；比较现有FGP速度扩展与可复用LFP后处理。先核查训练/传感器坐标、校准与时间，保留固定根pose-only作为诊断对照；需要训练速度/接触头时，先确认可信的监督标签。FGP扩展、LFP物理分支和简单脚速融合属于不同变量，不一次混改。
2. **生成合格A3机器人参考。** 保留原始人体轨迹，在重定向中结合机器人骨长、限位、支撑/摆动和地面；检查贴地、足滑、穿地、抬脚、root修正和关节速度。通过运动学只证明标签几何可用，下一步仍须动力学闭环。
3. **用冻结官方035测试。** 复用已有官方样例基线，在同资产/种子/时序条件下回放合格衣服参考。比较前進位移、步长/支撑交替、足滑、跟踪、跌倒与任务完成率。离线真实未来帧与实时约180ms缓冲/预测必须分开记录，不把离线成绩当零延迟遥操。
4. **仅对明确的剩余短板特调。** 若合格参考仍在官方控制器下失败，用衣服导出的合格机器人motion library暖启动微调035，保持已有G1/A3-fast接口，无需新增SMPL编码器。按完整采集序列/会话划分，保留未见走路段和官方基础回归集，不随机按相邻帧拆分。噪声/延迟增强采用测量范围，保持官方行为约束并逐项比较；不得把畸形参考造成的错误当成策略学习目标。

两类“衣服特调”要区分：FGP/速度/接触模型改善人体重建，A3策略改善机器人执行。若前者错，先修前者；若参考合理而后者失败，再调后者。衣服IMU不能直接作为现有035训练输入。该顺序是下一路线建议，本阶段没有登记或启动新计算实验。
