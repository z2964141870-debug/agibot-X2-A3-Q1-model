# X2 板端绑核对照与确认排队复核

## Done

同一时钟下复核三组板端记录，每组 900 个人体 RPC。按人体包开始发送时，串行 REP 是否正在处理已开始的状态请求进行分组。时间取板端 sender 记录的 ACK 与 RPC 耗时倒推。两类都可能出现此后进入的其他状态处理、线程等待以及传输长尾。

| 历史联跑 | 发送时已有状态处理中，RPC P50 / P95 | 当时没有状态处理中，RPC P50 / P95 |
| --- | ---: | ---: |
| r2_profile | 5.74 / 11.61 ms（484 包） | 1.41 / 12.55 ms（416 包） |
| dedicated_hosts | 6.13 / 11.66 ms（524 包） | 1.37 / 11.96 ms（376 包） |
| R3 独立 CPU 进程 | 6.43 / 11.05 ms（491 包） | 1.65 / 12.15 ms（409 包） |

三组中，发送时服务正处理状态的 RPC 中位均高约 4.33–4.78 ms，和原状态服务区间有 4.52–5.34 ms 中位重叠。P95 两组仍接近，表明避开已在执行的状态请求可减少常见等待，但还需要量化其他路径的长尾。这是排序相关性，不能简单扣除中位差作为绑核或跨机收益。此次没有重新推理。
