## 目标与实现

已有[真实输入审计](README_Q1_TELEOP_REAL_INTAKE_20261106.md)发现约26Hz、不均匀输入经离线插值会依赖未来支持帧。新增独立 `causal_resampler.py` 与 `recorded_causal_replay.py`，只按已经发生的到达事件处理姿态，不改50Hz H4/H5受控消融或原训练输入。

源标识显式区分payload与receiver时钟；原payload时间、上游依赖截止和接收ready时间分别保留，未知项保持null。输出目标为接收端到达时轴，所有间隔/估速均在该时钟内计算，不把payload epoch与host单调钟相减。到达时轴包含网络/感知抖动，不能称为硬件采集时间或物理速度真值。

| 固定方法 | 计划缓冲 | 行为 |
| --- | ---: | --- |
| hold_now | 0ms | 保持最后已到达姿态 |
| cv_now | 0ms | 最多5个不均匀到达样本锚定速度外推 |
| damped_now | 0ms | 同样速度估计，tau=.12秒阻尼 |
| linear_buffer40 | 40ms | 仅在左右支持都已到达后做位置线性/SO(3)插值；右支持未知时保持 |

速度上限固定3m/s、8rad/s，外推上限80ms、实际使用支持的新鲜度上限200ms、支持间隔上限200ms。超过范围输出明确不可推进状态，调用方必须处理回退，不把全零目标或无界外推交给策略。初始只有一帧时明确保持；乱序旧序号丢弃，重复包不刷新原到达时间，冲突和payload时钟倒退拒绝，容量最多256帧。

保持、插值与外推分别标记，`is_exact_measured_capture=false`。即使目标恰好等于到达时刻，也只称 `receiver_arrival_exact`。局部因果不认证FGP内部因果性；没有生成可直接冒充原 `measured_exact` 的策略预览帧。

旋转复用本仓库既有四元数/SO(3)函数；本机缺SciPy，没有新增依赖或改服务器环境。10项新边界/解析测试及2项固定录制回放检查通过，完整56项中54通过、2项服务器原运行时检查跳过。覆盖跨时钟原点不变性、不可预装未来、延迟插值支持、不均匀速度、旋转跨pi、限速/阻尼、过期/丢包、旧支持新鲜度、乱序/冲突、源重置和同到达批次。

## 固定真实录制回放

使用原两段TEST_ONLY身体小包，各场景读取前后核输入及inspection身份；不读原始大JSONL，不重做旧重定向/支撑物理。每包仅用自身 `axis_angle` 经固定SMPL parent组合当前帧世界旋转，位置沿用当前帧joints；软件坐标保留原SMPL轴，硬件轴/上游capture未认证。

两个场景预先固定：原记录到达，以及在相对30秒处人为略去250ms包。后者标作synthetic，不能冒充真实网络故障。参数在源码固定，不拿两段测试包拟合、选参数或训练。报告到达支持年龄、不可推进原因、计算耗时、输出相邻姿态的最大关节点变化；变化量不是跟踪准确度，也不是机器人自然性。

这项测试暴露了两个独立代价：40ms缓冲使这两段输出步变减小，但自身需要明确计划等待；常速度/阻尼外推的重锚定仍会产生较大跳变。3m/s、8rad/s仅限制预测斜率，不能保证新测量到来时的全局输出变化率。没有据测试包挑选最佳配置或调节阈值；后续若需要全局连续性，应在解析急停/换向场景独立明确限速/滤波与时间滞后合同，再做留出验证。

无机器人策略推理、物理、训练、CUDA或渲染。端到端实测延迟、物理跟踪准确度均为null；这些亚毫秒数字仅为本机当前单样本数值处理的耗时分布，未包含FGP、传输、机器人策略或执行器。
