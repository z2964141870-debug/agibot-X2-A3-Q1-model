# 头环与衣服：从人体世界运动到固定控制器可执行参考

记录日期：2026-10-14。侧支编号：HB01。状态：离线协议验证完成；创新方案待验证，尚未训练。

## 目标与范围

用户在侧边聊天要求引入头环、深入查资料并建立持续工作计划。本侧支研究补足衣服参考的全局运动信息，并验证其是否改善冻结官方035的实际跟随。它不接手主线程E49，不改动其账本、控制器、运行任务或自动化。原hp3090仅用于代码/Git和只读资料获取；本轮Mac仅标准库解析、文档阅读和小型记录。

重要区分：头环能提供额外观测，不等于已经获得可靠根轨迹；人体动作重建更准，也不等于机器人接触平衡更好。当前没有新增模型效果证据，官方035仍是基线。

## 已完成与实际证据

### 1. 厂商协议从“文字支持”推进到样例解码

重新核对用户提供的双目ZIP：70,754,608 bytes、378个文件，未整体解压，未安装或运行SDK/可执行程序。相机规格书第3–4页、时间戳指南全部3页已渲染核对。指南/源码与包内唯一BMP可建立一致的协议解释。

- 厂商说明图像同时含有效画面与数据编码区，不能直接把4000像素宽均分为两幅2000像素有效图。具体有效裁剪与内参仍须实物/标定核验。
- 文档支持可选ICM42688、曝光开始/结束和IMU采样时间。标称同步误差不是实测；SDK包含该协议不能证明用户这块头环已焊接IMU或启用相应固件。
- 独立实现`script/headband/nori_offline.py`，仅标准库、内存读取单张BMP，不落盘样例图、不接相机。明确BMP偏移/行对齐/方向、协议版本/组数/截断和无效传感器值。
- 解码样例4000×1200、24bit：192 bytes编码载荷、96条编码行、11条有效IMU数据。曝光开始28,117,353 us，结束28,124,847 us，持续7,494 us；与指南截图独立转录一致。10个相邻IMU间隔均1,664 us。仅能说明这一张厂商样例，不能据此报告实物持续采样率、掉帧或同步性能。
- 13项控制通过：大小端/物理单位、无默认量程、无效哨兵、截断、未知协议/设备、越界组数、BMP行对齐/偏移/方向、缺前缀、32bit回绕及重复/倒退时间、指南黄金头。
- 解码默认只输出原始量。厂商示例默认加速度±4g、角速度±1000°/s不当作实物配置。加速度函数实际输出mg，陀螺函数输出deg/s，而终端陀螺标题写1/1000(dps)，存在标签不一致；新解析器采用显式量程后转换到m/s²和rad/s。
- 32bit微秒计数约71.58分钟回绕。跨流时间不能分别从零累计后直接相减；要共用epoch、处理复位，并估计相机与衣服时钟偏移/漂移。当前小工具只验证同一连续流的有界相邻差，不声称实现全部跨时钟融合。
- 源码有`memset(...,0,0)`零长度清零，以及固定BMP布局等通用性问题；本轮未运行厂商源码。协议未见CRC定义，合法灰度位翻转未必可检出；解析成功不代表完整性校验。

结果：[协议小清单](../data/manifests/headband_protocol_result_20261014.json)。来源节选仍为LOCAL_ONLY，不提交厂商PDF/SDK。

## 关键决定：先解决观测问题，再验证控制收益

已存在的[9月29日头环分析](EgoLocate与头环分析.md)讨论过视觉+IMU、GRU、新鲜度门控、头部动态外参、双目深度和接触。因此这些不重新包装为原创。

优先通路：

```text
衣服姿态/历史 ───────────────────┐
双目/头部IMU → 头部世界运动 → 时钟与动态头身补偿
                                 ↓
                        人体根轨迹及不确定性
                                 ↓
           有界参考修正 ← 机器人支撑状态及对误差的敏感程度
                                 ↓
                  既有重定向 → 冻结官方035 → 同条件效果评测
```

1. **世界观测与人体形变分开。** 约定`T_AB`把B坐标映射到A。`T_WC = T_WP · T_PH(q) · T_HC`；相机世界位姿需通过随姿态改变的骨盆到头部变换与固定相机到头部外参，才能恢复骨盆。固定camera-to-pelvis外参会把转头、弯腰混进根运动。HB02先做“骨盆固定、转头”“相同动作改变世界坐标原点”的解析控制。
2. **地图修正与真实运动分开。** SLAM重定位可改变地图对齐；机器人参考应在连续局部坐标中保留真实运动，不能把重定位跳变微分成根速度。失去追踪要表达不确定性，而非用长时间停止参考假装稳定。
3. **本侧创新候选：按控制后果处理感知误差。** 同样1cm误差，对腕部显示、支撑脚和摆动脚落点的影响不同。提议在冻结035条件下，通过有界反事实参考扰动，估计“参考误差→接触/跟随风险”的局部方向敏感度，再据此调整各方向的修正权重。只按感知协方差融合是必要基线；加入机器人后果信息才是待验证增量。`JΣJᵀ`等不确定性传播本身是已有方法，不声称原创或安全证明。
4. **先固定一个主变量。** 第一比较仅改变权重是否使用控制敏感度，冻结重定向/035/目标/速度/相位。不要同时引入时序改写、RL奖励修改和大模型重训。仅在确定性路线暴露可学习短板后，训练小型风险或参考残差网络；不从零替换人体编码器。

## 原始研究核验与创新边界

论文原始地址、实际检索层级及待核验项见[来源清单](../data/manifests/headband_sources_20261014.json)。以实际读取的正文/仓库为准，搜索标题不算复现；本轮未下载模型或运行任何论文代码。

- EgoLocate：头戴视觉与6个身体IMU进行运动捕捉/定位/建图，作者仓库的TotalCapture合成视角使用还要求先获得原数据许可；不能直接当本站衣服域的免标定训练数据。
- EgoHDM：正确原文入口arXiv:2409.00343，单个RGB头戴相机与6 IMU、在线建图和地图相关人体物理修正；不是“必须RGB-D”的方法，也不直接提供A3机器人的动力学可行性证明。
- RoSHI（2026-04-08，arXiv:2604.07331v1）：已核验摘要和HTML方法/人形控制/局限段落。低成本IMU+Aria眼镜、扩散人体先验加骨向约束、重定向后人形学习，直接覆盖“衣服+头环→机器人”宽泛构想。文中观察到机器人为追随人类根轨迹而加速，提示必须共同评价步态时间与位移；约束冲突造成扭转也是明确局限。不能直接当作我们的实时延迟/因果性或硬件适配已验收。
- EgoAllo（2024-10-04首发，页面最新v3为2024-12-17）：原文摘要/版本及作者仓库README已查。它用头部SLAM与视觉条件扩散重建全身，现有训练代码不等于可直接使用；输入包括Aria VRS/MPS输出，数据与SMPL-H有各自使用条件。暂不装其新依赖或重训大先验。
- HPS（2021-03-31）：摘要与日期已核验；融合身体IMU、头戴视觉与预先扫描的环境，并使用地面接触约束，作为“加接触”已有先例。
- 其他近期候选只有通过原文标题、发布日期及方法核验后才进入正式比较；不以未经核实的检索片段作为新颖性结论。

EgoHDM正文还承认所复用人体先验会软化动作、膝盖未充分弯曲。这是与本项目下蹲有关的**候选解释**，必须用原始衣服/SMPL与对应输出对照，不能直接说本项目失败已定位。之前提及的SPOT线索本轮未完成原文独立核验，不纳入研究结论。

## 结果、验收与下一步

结论为“值得开展离线可行性研究”；训练就绪状态为否。尚缺实物型号/IMU/量程、双目与头部标定、相机与衣服跨时钟关系，以及独立参考真值和完整会话划分。现有厂商样例不能训练人体根运动。

评测看原人体目标在原时间上的根/腕误差、实际位移、脚滑/接触、跌倒、延迟及参考改写幅度。禁止只用动态时间对齐分数，禁止靠不走/慢走/缩短步长过门；人脚接触不等于机器人支撑。旧7段衣服开发片段不是未见测试。
