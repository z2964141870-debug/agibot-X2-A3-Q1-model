# SuperMimicHP 与 Q1 双向核查及根反馈对照

记录日期：2026-10-26，北京时间。阶段 HPR01：实际源码对照、根反馈实现和V02端到端验证完成；RF07已于19:48:55按核验发布代码启动。用户要求既找本项目缺失/不合适之处，也审查师兄实现，适用且有效的方法积极采用。不开子agent；新训练每轮最多3600秒。

## 结论与证据层次

1. 本项目确认缺少actor直接可见的根位置和参考朝向误差。`q1_sim.py:105`仅返回本体历史和参考窗口；`heads.py:148`根漂移只供critic。两种位置不同而姿态/速度相同的状态，对原actor可以完全同输入。原有`anchor_relative_obs`及`imagine(anchor_obs=True)`已经实现可微反馈，但正式入口未启用。奖励含根位置项不等于actor观察到了漂移。
2. 力矩上限不是动作尺度。Q1原来同时采用25%力矩上限和以25%型号力矩计算动作尺度；X2动作尺度中的0.25并不将实际力矩封顶25%。RF06腿限矩50%后仍98.904%双支撑，只有1.49cm净位移，因此没有证据继续只调限矩就能学会走路。X2逐关节PD源于估计惯量，不是Q1厂家参数；本轮不照搬数值。
3. 两边主要奖励权重/带宽和根XY+yaw重锚公式相近，未发现足以支持直接加大位移奖励的独有差异。Q1奖励/终止对`step`前的目标帧计算；X2想象奖励使用推进后的目标帧，两者相差20ms，属于需要统一核查的时序差异。本轮先保留Q1时序，不能同时改动后把改善归给根反馈。
4. RF06实际600采集轮但仅139次actor更新。X2记录的24k是24k优化迭代，最终61,571,072转移，不能拿600与24k直接作为同一计数比较。X2实际1024环境、100条SOMA训练、15条演员留出、GPU mjwarp；本项目4096环境、CPU MuJoCo、单段365帧。更多环境既不增加动作种类，也不自动增加噪声幅度；一小时内更新吞吐仍是本项目实质短板。
5. 目标信息也没有完全对齐。X2的`motion.py:155`把未来1..10帧的相对根位移、6维完整朝向、局部根线/角速度、关节位置/速度放入目标；当前Q1用当前..第9帧的关节位置/速度、投影重力、角速度、heading线速度及高度，没有未来根相对位移和完整朝向。Q1想象起点也没有X2的H32片尾有效起点限制，而是到片尾重复目标。均列入明确差异清单；RF07先只改当前根反馈，后续再分别核准，不将所有差异一次混入对照。

X2 root_xy接口同时用于真实采集与世界模型想象，含相对根朝向和heading-frame XY误差，机制正确，已有作者发布的同7k配对改善。尚未独立复跑，不能当成本项目Q1的实测收益。其零硬终止没有被直接当成全动作跟踪成功；24k报告保留快走约0.15m根RMSE、约0.99m/s近地材料点速度代理及留出窗口退化，拒绝48k是质量决定。近地速度不是接触力/真实接触滑移测量，真机根位置估计也未因此验证。

发现一个可定位的边界风险：learner的`_sample_valid_starts`使用无上限`while count < batch_size`；MotionLib只要求输入至少两行，当全部片段都不足H32时无合法起点，循环没有退出路径。用实际函数AST加假replay/空有效掩码有界复现，不运行X2训练，也不证明其当前100条长片触发该问题。建议初始化检查存在合法H32参考，并为采样加有界失败出口。反馈写在本记录交给用户，没有代发私信或GitHub issue。

作者报告同12k权重两次复评留出整段根RMSE为0.09056894m/0.08893359m，约1.8%差异，原因未证实；当前成对复评避免挑选历史基线是合理做法，仍应核查确定性、后端与资产身份后解释差异。此项属于待定位疑问，不冒充已证算法错误。
