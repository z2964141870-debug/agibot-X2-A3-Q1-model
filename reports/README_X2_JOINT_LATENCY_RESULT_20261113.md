# X2 联合延迟结果

2026-11-13，SoC1真实联合运行：FGP CANO GPU＋其余FGP和Morph CPU＋真实机器人反馈＋原生observe后端。输入为约31秒连续真人衣服IMU录制，按30Hz释放；未连接新BLE，电机命令和MC修改为零。

按作者“只取最新帧”调度，计入原180ms预览跨度：**后端目标对应的人体参考年龄中位约297–310ms，p95约341–356ms，最大约495–510ms**。这是同机软件参考年龄的保守上下界，不是传感器采样到机械响应的实测延迟，亦不是动作相位GT。

| 项目 | 实测 |
| --- | ---: |
| 完整FGP中位 / p95 | 41.56 / 63.42ms |
| 人体输出实际频率 | **17.81Hz，未达30Hz** |
| 输入到HumanFrame确认中位 / p95 | 72.70 / 96.19ms |
| Morph全部ready RPC中位 / p95 | 12.63 / 22.96ms |
| 超20ms被拒请求 | 133 / 1456次ready |
| 跳过的过时输入 | 363 / 929帧 |

Morph仍约48.5Hz生成建议请求，但读取的人体新信息仅约18Hz；不能当成50Hz人体遥操。跳帧后模型及物理仍固定30Hz，动态/姿态质量未验证。首个策略输出需要约1.25秒填充历史和预览，和稳态延迟分开统计。

诊断FIFO组证实：若坚持处理全部输入，末尾会积压约21秒，因此必须避免旧帧队列持续增长；作者实时入口本身已使用最新帧，并非已部署入口存在该21秒延迟。温度最高69.34度，最低可用内存约10.83GiB，未触资源保护。

结论：链路已能同机跑通并测到真实软件年龄，**当前仍不满足稳定30Hz衣服遥操**。下一步优先拆开FGP、骨架转换和同步通信，再定位CPU线程/ROS竞争；180ms预览也是独立改进项。BLE无线和真实机械响应尚未测。
