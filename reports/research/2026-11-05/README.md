## 1. SONIC-K1 v1.0：把实际电机和延迟放回训练

机器人在理想仿真里跟得上，到了真机可能因力矩不足、指令滞后而抖动。今天的版本增加较低的部署限矩、逐步扩大的 0–40 ms 指令延迟、PD 增益随机化和接近限矩的惩罚，另公开部署控制器。原文中“real-robot condition”表格仍是 **MuJoCo 仿真**：作者报告，1,985 条未见动作、10 秒片段、40 ms 延迟下，按 SONIC 成功规则从 76.7% 到 96.6%；更严格规则为 58.5% 到 89.1%。作者另声明已在实体 K1 运行，但这两个成功率不是实体测试统计。

与 Q1 的关系：后续应区分参考误差、执行限矩与延迟，不能只看不摔倒；也不能直接复制 K1 力矩数值。**证据：固定提交的八份文本/源码静态核验，未运行或复现。** 正式 v1.0.0 发布已确认；作者标注代码 Apache-2.0、权重 CC BY-NC 4.0，Hugging Face 权重入口本轮超时，文件与许可资产未独立核验，BONES 数据不随仓库分发。**建议：现在登记版本与评测口径，基线完成后再试。**

## 2. iLQR-MPC：落脚点与接触力需要一起决定

把身体当成一个带姿态的刚体，控制器每次同时调整“下一脚放哪里”和“脚向地面施多大力”，再由全身控制分配到关节。这能帮助理解：身体没倒、关节误差变小，仍不等于迈出了合理的步子。

作者报告 G1/MuJoCo 中 MPC 100 Hz、平均求解 8.9 ms，底层全身控制 500 Hz。但步行仅 0.1 m/s，推力被假定已知，部分瞬间求解超期；接触时间表和名义参考仍由上游给定，未验证真机。**证据：原文相关方法、实验及局限；未核到作者代码、权重或复现。** 对 Q1 目前只帮助解释接触/移动诊断，不能由此认定现有失败原因。**建议：现在理解评测，控制器替换只作背景。**

来源：[原论文 v1](https://arxiv.org/abs/2611.04204v1)。

## 3. Action-Grounded Foresight：先问动作是否推进任务

它先提出多组身体与手部指令，预测各组会到达什么视觉状态，再结合动作的时间连续性评分；只执行胜出方案前一小段，看到新画面后重选。额外训练一个“从视觉变化反推指令”的模块，促使预测保留动作信息，避免只生成好看的未来。

这对应项目未来的物体操作评测：姿态合理不保证抓稳或任务完成。但它预测视觉终点，不是当前 Q1 的关节/接触动力学世界模型。作者的任务成功评测用桌面 GPU；机载 Orin NX 测试只有 **0.73 个动作块/秒**，不是低层关节控制频率，而且依赖每任务示教和子目标。**证据：原文相关方法、设置、消融和局限；代码/权重未确认，作者页下载不完整。建议：基线完成后再试。**

来源：[原论文 v1](https://arxiv.org/abs/2611.04839v1)。

## 4. ReflexArc：保护反射要快，跟踪策略也要配合

触觉发现碰撞后，独立通道直接给电机撤离偏移，同时训练慢速全身策略保持平衡并接受这次偏移。否则策略会把撤离当成“偏离参考”而拉回去。作者报告 G1 触觉至电机响应小于 10 ms；给同一反射额外加 20 ms，碰撞更重，原实验无额外延迟时首个力峰低 34.1%。

对未来头环遥操，价值是明确“人给的参考”和“本地保护”怎样共同控制；它不消除网络延迟，也不让头环自动获得触觉。需要额外皮肤、标定和策略训练，未覆盖皮肤区域仍无保护。**证据：相关原文与作者页，未复现；作者页 Code 为 Coming soon，训练代码/权重未确认。建议：只作长期背景。**

来源：[原论文 v1](https://arxiv.org/abs/2611.04424v1)；[作者页](https://minusmodulo.github.io/reflexarc-website/)。
