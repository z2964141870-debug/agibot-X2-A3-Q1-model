# 第一课 · 第四小节：怎样检查奖励是否鼓励了正确行为

记录日期：2026-09-30。阶段：L01-S04。状态：奖励设计讲解与检查表已准备，尚未在机器人训练任务上实施；clip 的作用仍需巩固。本次只维护教学记录。

## 目标与学员反馈

上一题问：错误评分使摔倒经历获得更高累计回报，只调小 clip 能否解决？学员答：“能，可以防止由于错误的奖励设计而导致的大幅偏移，然后我还想问，那要如何防止出现奖励设计A？”

这次回答包含一个合理的局部认识：PPO clip 有助于抑制更新过猛。但它不能修正错误目标，也不能严格保证单次或累计参数变化很小。即便每轮只向错误目标前进一点，多轮更新仍可能逐渐学偏；每轮采集时使用的旧策略也在变化，clip 不是把策略永远限制在最初模型附近。

本节直接回答如何检查奖励设计，不要求学员再次重复上一道判断题。补充解释不代表已经验证学员掌握 clip。

## 先分清失败经历与错误评分

原例 A、B 是两段假设经历，不是两个奖励函数。A 的回报 `5+1-12=-6`，B 的回报 `2+2+2=6`；至少在这对例子、相同起点及不打折的设定下，评分把稳定完成的 B 排在了前面。A 首步得 5 不构成评分错误。

训练早期探索到失败动作可以发生在合理的奖励函数下。若奖励配置持续让摔倒、不动或抖动等任务失败获得比成功更高的预期回报，才说明评分与任务要求存在明显冲突。单次高分失败也可能来自随机性，需要保留经历并核查，不能只凭一条曲线下结论。

## 面向第一次上肢跟踪训练的检查方法

### 1. 写下可测量的成功条件

沿用[训练工作包](训练工作包.md)的目标：机器人在双脚支撑、浮动基座动力学下，跟踪固定低幅上肢动作。

成功应同时包含完成参考动作、跟踪误差满足要求、全过程保持规定支撑与姿态。具体误差、持续时间和终止阈值要等匹配机器人资产与任务核验后制定，并在比较实验前固定。本课不臆造 X2/A3/Q1 可直接采用的阈值。

独立评估至少记录跟踪误差、跌倒率及完整动作成功率；按需要补充抖动、足部滑移、力矩饱和比例。站着不动即便不倒，也不能算完成跟踪任务。

### 2. 从已验证的同类任务奖励配方起步，理解每一项

教学层面的组合可以写为：

```text
reward = 跟踪得分 + 姿态稳定得分
         - 过大控制用量的代价 - 动作突变代价 - 跌倒惩罚
```

它只展示构成，不是确定的公式、权重或运行配置。实际选择需核对任务需求和成熟实现；并非所有任务都用上述全部项。

逐项记下原始量、归一化、符号、权重、加权后的实际数值及是否每步生效。不能只比较权重数字：不同项的单位、取值范围和作用次数都不同。长回合中反复得到的跟踪奖励，可能超过一次跌倒惩罚；惩罚无限增大也可能让策略选择完全不动。

### 3. 用典型成功与失败经历检查总评分

先人工审查简单例子，随后用真正推进动力学的仿真记录复核。冻结起始状态、参考片段、评分版本和计分规则；下表是待采集的检查清单，目前没有对应机器人实测轨迹。

| 经历 | 按任务应怎样判定 | 重点检查 |
| --- | --- | --- |
| 稳定完成参考动作 | 成功候选，还需满足误差等阈值 | 完整回报是否能体现完成任务的价值 |
| 始终站着不动 | 跟踪任务失败 | 存活或姿态奖励是否掩盖未完成动作 |
| 快速到达目标后摔倒 | 失败 | 早期得分是否抵消后续失败代价；后续结果是否被纳入估计 |
| 在目标附近反复抖动 | 不能仅凭接近目标判成功 | 是否反复刷到进度得分，或动作变化项没有实际作用 |

核心检查是：已知明显失败是否在评分上稳定优于成功。失败案例之间不预设统一排名；不同任务可能采用不同取舍。人工构造案例有覆盖局限，不能证明所有失败都已排除。

比较实际用于训练的回报时，计入折扣、控制周期和提前结束规则。原三步例子设 gamma=1；若仅作数学演示改为 gamma=0.1，则 A 为 `5+0.1-0.12=4.98`，B 为 `2+0.2+0.02=2.22`，排序会反转。这个极端值不是调参建议，只说明“以后摔倒”若被折扣得过轻，目标也会改变。

终止处理也会改变得分机会。例如每一步只有负成本、摔倒又立刻停止所有计分，可能使提前摔倒逃掉之后的扣分。跌倒应按任务定义处理真实终止；采样时间上限、回合时间上限与真实失败的价值续接规则需分别核对，不能一律当作同一种结束。

### 4. 用短训练和独立评估验证，再改一个主要变量

先通过 P0 的训练、保存、重载，复现匹配任务的基线。对固定评估初始条件和参考片段，保存分项奖励、总回报及真实任务指标；对照视频定位失败原因。总 reward 上升而跟踪成功率下降时，优先检查评分与任务的对应关系，也检查观测、动作和执行器实现，不只调 clip。

每次只设一个主要改动，例如某项权重或一个评分漏洞的修正，并保存配置、命令、分项日志、评估结果及失败轨迹。形成结论时再用多次重复和独立评估条件检查稳定性，不能凭一次训练宣称有效。

## 边界与下一步

奖励设计依靠明确需求、反例检查和实验逐步改进，没有通用公式能保证训练时永不失败。参数优化机制与任务目标是不同问题；执行器限位等约束也应在对应实现层处理，不能期待 PPO clip 自动提供这些约束。

这份清单尚未实施，未调整任何实际训练奖励或 clip 参数。下一步结合学员问题，读取选定完整训练任务中的跟踪项、失败终止和分项日志，解释其对应量；P0 仍按[核验记录](README_P0_INSPECTION_20260930.md)推进。随后再连接 critic 与 advantage，不把它们当作自动修正任务目标的方法。
