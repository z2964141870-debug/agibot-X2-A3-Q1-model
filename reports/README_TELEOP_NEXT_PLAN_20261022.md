# 传感衣遥操下一阶段计划

记录日期：2026-10-22（北京时间）。阶段：TELEOP-PLAN-01。状态：计划整理完成，以下实验尚未执行。

## 目标与范围

用户询问接下来计划做什么。近期目标是用已确认的CLOTHO-mocap代码建立人体估计、A3重定向和冻结控制策略的配对证据，找出最值得改进的环节；长期目标是形成可复现的遥操改善及论文。当前优先A3，后续再考虑G1扩展。

本轮只读取最新资源/上下文记录并保存计划，没有迁移新代码、加载模型、推理、仿真、训练或操作机器人。计划中的后续科学执行尚未开始，不恢复历史STOPPED实验。

## 已有依据与关键决定

- 当前FGP代码以用户提供的`/Users/yu/Downloads/CLOTHO-mocap-main.zip`为准，主干权重基本复用。此包在线LIP显式采用tanh，与旧ReLU入口不同，需要新版本的基线。
- `stage_tran`默认开启，但`root_velocity.pth`、`foot_geometry.pth`尚未定位。缺失时可单独验证姿态分支，完整位移/脚部修正分支等待依赖，不用补零轨迹声称完成移动跟随。
- 历史T10标签参考自身A3 IK P95约6.4cm，预测参考约6.1cm，均超过既有5cm质量门；肩、膝重定向误差尚未解释。这是既有短片段证据，本轮未复算。
- 035继续作为固定控制比较基线；M17保留为旧口径候选。旧微调、参考残差及失败结果需读取，不能把重复方案称为新研究。

证据入口：`reports/README_TELEOP_RESOURCE_INVENTORY_20261022.md`和`reports/README_TELEOP_CONTEXT_REVIEW_20261022.md`。

## 推进顺序与验收

| 顺序 | 计划工作 | 产物与通过条件 |
| --- | --- | --- |
| 1 | 固定新代码、复用权重及数据身份；建立不启动硬件/socket/Unity的离线入口 | 代码/权重SHA、传感器顺序、标定、单位、坐标、时间与状态重置合同；严格加载与有限数值通过 |
| 2 | 新代码配对人体基线：先取走路、抬腿/单腿、转身或下蹲等少量已有开发会话 | 同场输入、标签和预测逐帧对齐；分报根相对关节/角度、脚腕误差、抖动与因果延迟；有训练曝光只称诊断 |
| 3 | 使用同场标签姿态和预测姿态检查A3重定向 | 先解释标签臂肩/膝残差，核骨架映射、尺度、坐标、限位、接触/根处理；保留既有IK P95不超过5cm门，不以放宽门代替修复 |
| 4 | 参考合格后，用冻结035完成匹配动力学回放 | 同动作、时段、初始化、控制条件；比较标签参考和预测参考，分报共同人体目标误差及各自参考跟踪误差、跌倒、滑脚、时延 |
| 5 | 根据误差来源选择一个主要改进变量，再做独立测试 | 估计主导则改人体/参考；几何主导则改重定向；合格参考下执行主导才考虑策略适配。与简单基线同预算比较，保留未见会话，最后再扩展机器人和真机 |

步骤2、3可使用同一小批数据分别诊断。完整stage_tran依赖到位后，在相同姿态输入上单独比较开启/关闭，区分根位移与姿态修正的影响；有可信同步世界轨迹才评价世界位移精度。若只有标签辅助根/接触，必须标明离线条件，不能称完整实时系统。

新数据划分应按人员/会话及采集条件隔离，具体划分取决于可用元数据。已多次用于开发的v7和FGP发布训练集不能当新的最终测试。无可信标签的共享盘会话可用于鲁棒性、丢包、时序和工程检查，不编造姿态精度。
