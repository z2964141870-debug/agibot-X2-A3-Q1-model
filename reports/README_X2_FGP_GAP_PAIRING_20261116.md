# X2 FGP 快慢帧间隔归因

## Done

只读复核四轮分阶段探针。源帧固定约每 33.33 ms 释放，四轮各有 210 个相邻 FGP 出帧间隔，零跳帧。逐纳秒校验，相邻出帧间隔等于源间隔加两帧间的起算迟到、GPU 主机阶段、CPU 入队、CPU 重建耗时的差。GPU 主机阶段再区分 IMU 标定、CANO 主机调用及剩余部分；CPU 重建再区分原生求解和其他时间。每个长间隔按相对上一帧的最大正增量归组。

| 线程配置 | 出帧间隔 ≥40 ms | ≥40 ms 后紧跟 <30 ms | 最大增量落在 GPU 主机阶段 |
| --- | ---: | ---: | ---: |
| 4 线程，两轮 | 76 / 420 | 46 / 76 | 62 / 76 |
| 2 线程，两轮 | 85 / 420 | 60 / 85 | 76 / 85 |

2 线程的 85 个长间隔细分后，最大增量在 CANO 主机调用 29 个、其他 GPU 主机处理 28 个、IMU 标定 16 个，另 12 个在启动迟到或 CPU 段。GPU 主机时间含 CPU 工作与同步等待。它不能直接归到 GPU 算力、系统调度或某个 CUDA 算子。

2 线程的帧 129 出现 56.89 ms 间隔，下一帧为 18.33 ms。长间隔的同帧主要增加来自 CANO 调用 13.44 ms 和逐帧标定 5.70 ms。这个成对现象说明平均接近 30 Hz 时，新人体参考仍会成组到达。策略在长间隔中可能多跑几轮相同或相近参考，短间隔后一次取得更新的窗口。体感仍取决于策略对时间戳和窗口的处理，不能用日志直接预测机械动作。

本轮分析的是 FGP 出帧，历史 HumanFrame 确认还存在独立的下游长尾。这组输入以固定录制时钟释放，因此定位的是板端处理阶段。真人穿戴时还需要对照 BLE 采集和到包时序。只读分析未重新运行 FGP、策略或机器人。板端原件和 Mac SHA-256 核同。
