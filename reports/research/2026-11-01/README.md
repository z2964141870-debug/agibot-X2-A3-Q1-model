1. **MorphMimic v0.1预发布：增加人体输入和统一策略资产。** 它将身体结构信息交给共享世界模型与策略；新的人体编码器可接24个SMPL关节，或骨盆、双腕、双踝五点，再使用同一个动作解码器。对衣服/头环遥操，这提供了“人体目标如何进入策略”的具体接口，而不是只谈融合。原始预发布为10月30日02:13:25 UTC（北京时间10:13:25），固定源码`770394b4`；已静态核README、Apache-2.0许可、人体标定和延迟实现，公开约63.4MB的ONNX策略包元数据，未下载。作者只报告G1真机，X2 Ultra/T2为仿真，没有Q1；原多本体训练需三GPU。人体路径不需要机器人姿态重定向，但不等于解决精确手姿、头环SLAM或全局漂移。**现在做：阅读与现有冻结版的差异；新版本接入放在基线完成后。** 不能把我们的单G1训练叫作unified完成。[代码](https://github.com/lzyang2000/morphmimic/tree/770394b4a0cad9effbf807a6c03435d1699733d0) / [v0.1](https://github.com/lzyang2000/morphmimic/releases/tag/v0.1)。

2. **智元官方SONIC for A3：089策略和XR遥操流程公开。** 新材料把训练、仿真到部署及PICO输入链连起来；089同时改变刚性脚、动态踝、执行延迟、自接触和腕部目标/奖励，适合学习真实执行器与手腕目标应如何写成明确契约。README发布日10月30日，固定提交`ac5d5f5c`为10月30日07:49:22 UTC（北京时间15:49:22）；已静态核配置、XR发布器、检查点说明与资产清单。源码及作者声明的PT/ONNX/RKNN为Apache-2.0，HF访问超时，权重仍未独立验收；原训练动作库不随仓库发布，20条示例只够软件烟测。没有SMPL编码器；10帧、间隔20ms的参考窗口也不是端到端延迟实测。多处一起改变，没有消融能证明某项单独改善步态。**现在做：读A3控制/资产契约；平台接入与调参待当前基线完成后。** [官方仓库](https://github.com/AgibotTech/sonic_for_a3/tree/ac5d5f5cbb3a34751a1064225412a5a1c04778bb)。

3. **SONIC-K1：“单GPU迁移”要连算力和成功标准一起看。** 作者给小型K1重做本体、重定向与控制接口，沿用SONIC/PPO路线。论文v1为10月29日04:16:33 UTC（北京时间12:16:33），10月31日首次发现。作者用一张共享H100 NVL、16384环境、50000轮，耗时135.4墙钟小时，折算约103独占GPU小时；不是单3090一小时方案。论文作者报告20ms/40ms延迟下成功率98.5%/56%，提示部署延迟值得单独测，但不能据此判定Q1故障。已读相关正文和固定仓库文档/完整树；权重入口存在但HF未核，原动作库不分发。README称权重CC BY-NC 4.0，而根LICENSE沿用上游NVIDIA权重条款，范围有冲突，不能称许可已厘清。网页仍写真机待做，论文只给初步定性真机结果且步行/转向不可靠。**现在做：借鉴预算、延迟和评测口径；不切换训练框架。** [论文](https://arxiv.org/abs/2610.39327v1) / [代码](https://github.com/Kyk0/sonic-k1/tree/e87ebd19b043c4effd7e31825bb80d0d96a12631)。

4. **FORGE：先生成考虑动力学的参考，再训练全身跟踪。** 它先在“单刚体动力学+完整人体运动学”的简化模型里学参考生成器，再冻结它，让完整机器人策略在线跟随。对我们最有用的分解是：参考要求是否可执行、控制器是否跟得上，应分别检查。v1为10月27日21:12:51 UTC（北京时间10月28日05:12:51），10月31日首次发现；已读方法、接触/奖励与实验正文，代码/权重未在所查入口定位。简化模型忽略肢体惯性，作者也承认与完整动力学有差距，不能把“参考生成”当物理保证；高速/持续跳跃的仿真和真机边界亦不同。**基线完成后再试；现在只用作解释参考误差与跟踪误差的背景。** [原文](https://arxiv.org/html/2610.37974v1)。
