## 阅读与研究优先级

1. **当前主线：完成第一次策略训练。** 优先 PPO、动作跟踪、机器人资产、可复现训练配方、仿真到真机。
2. **直接相关：衣服与头环遥操。** 人体到机器人的重定向、跨本体迁移、X2/A3/Q1 接口、全身控制、手腕精度、遮挡、时间同步、SLAM 与延迟。
3. **方法候选：跨领域借鉴。** 有选择地关注语言模型的记忆和测试时计算，以及状态估计、控制、不确定性、系统调度等方法；必须指出它解决本项目哪个具体问题。

论文、软件、模型和真机能力不是同一证据层级。新闻不触发自动换框架或自动训练。科研候选见[想法清单](research/README_IDEAS.md)，训练主线见[当前状态](README_CURRENT_STATE.md)。

## 每日检查步骤

1. 先读 AGENTS、当前状态、本文件和去重清单；通过 SSH 核实服务器 Git 状态并优先读最新记录。不要用过期本地副本覆盖远端或并行工作。
2. 检查过去 24–72 小时及上次成功检查以来的变化。间隔很长时优先最近 7 天并说明未覆盖时段，不声称完整覆盖所有领域。
3. 从 [arXiv cs.RO](https://rss.arxiv.org/rss/cs.RO) 与具体方向的原始论文/项目入手；按需查 cs.LG、cs.CV、cs.AI 和官方机器人、训练框架、SDK 仓库发布记录。媒体文章只用作线索。厂商能力、平台支持和代码可用性必须回到原始材料核验。
4. 将“首次提交、版本更新、代码发布、今天首次发现的旧文”分开，保存原日期及其时区、检查时间、版本、原始链接。arXiv 当日推送不等于当日首次发表。
5. 按论文 ID/版本、项目 URL/发布版本去重。只重复报告方法、实验、资产或可复现性上的实质变化，说明变化内容；不重复转述同一论文的多家媒体报道。
6. 每项写清：解决什么问题、核心方法、项目用途、证据和开源状态、局限、下一步建议。数字标为作者报告；只读摘要就不能写成已审完全文；未检查代码不等于没有开源。
7. 保存当天 README 与来源清单；有新假设才更新想法清单。重要工作按项目规范记录、审核并同步 GitHub。

优先选择对当前任务有直接帮助、证据较强且有可实行下一步的条目。炫技视频和很远的任务可以不入选；“今天没有值得行动的新内容”是允许的结果。

## 如何把跨领域方法变成研究问题

跨领域迁移是很好的选题来源，但换一个应用名不能单独证明算法创新。每个候选使用以下链条：

**已有方法 → 本项目可测量的瓶颈 → 机器人约束下的具体改造 → 最小实验 → 对照与消融 → 否定条件。**

在投入实现前，查方法名称及同义词、机器人/控制中的先行应用、相似故障场景和论文的相关工作。搜索有限时，只写“尚未确认新颖性”，不写“没人做过”。已有方法在这里不适用的具体原因、解决该原因的方法与实验结果，才可能构成贡献。

每次只选一个最值得验证的假设，先跑最便宜的离线或仿真实验。首要比较对象通常是现有实现、简单滤波/延迟补偿和同预算的小模型。复杂方法若不能超过这些基线，就降低优先级。达到阶段里程碑后再选题，不因每天新论文而频繁改变训练路线。

GitHub 仅保存关键研究文档、小型清单和配置。同步前检查远端状态及 diff，只提交本次有关文件，运行 `script/project_tools/audit_git_payload.py`，推送后核验；不强推。SSH 不通时先保存本地并注明待同步，不能把本地成功当成远端成功。

检索失败时记录已覆盖与缺失的来源，不虚构“今日最新”。同一未变化故障不重复打扰；出现新失败或需要用户处理时说明。自动任务只检索、分析并维护研究记录，不安装依赖、执行陌生代码、下载大型权重、启动训练或操作真机。
