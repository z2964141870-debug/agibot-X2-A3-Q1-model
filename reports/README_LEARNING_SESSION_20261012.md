## 第二轮反馈：PD 何时计算、输出什么

本人原话：

> pd的误差，是0.05吧，用0.25-0.2的，pd应该是已经介入运动时候的数据了

已答对：本题 PD 位置误差为执行目标减实际角，即 `0.25-0.20=0.05 rad`。参考与实际的跟踪差仍为 `0.30-0.20=0.10 rad`；这两个量用途不同。

对“已经介入运动时候”的解释：若指 PD 使用执行环节的实际反馈，这个方向正确；仅凭这句话不能认定本人误以为关节必须先动。进一步说明：代码每个物理子步先读取当前实际角 `q` 与角速度 `dq`，计算并写入力矩，再执行 `mujoco.mj_step`。静止时也有当前反馈，PD 不需要等待关节已经运动。

对应实际源码 `direct_pd_torque:2746`，省略配置对象前缀及类型转换后：

```python
torque = kp * (target - q) - kd * dq
```

量的含义：`target` 为执行目标角，`q` 为实际角（rad），`dq` 为实际角速度（rad/s），`torque` 为控制力矩（N·m）；`kp` 与 `kd` 调节位置纠正和速度阻尼的强弱。`kp` 单位为 N·m/rad，`kd` 为 N·m·s/rad。当前只解释公式意义，不调整参数。

前半项按角度差纠正，后半项按角速度提供阻尼。仍用目标0.25、实际0.20的假设，若关节静止则 `dq=0`；在 `kp>0` 时公式仍给出非零力矩。这说明力矩可以使原本静止的关节开始运动，不是已经运动才有 PD。

小回顾：参考规定希望跟随的动作；策略输出经缩放/基准姿态转换为执行目标；PD 根据当前实际角与速度计算力矩；物理状态变化后反馈进入下一次控制。策略输出本身不等于已经发生的运动。

下一项仅一个判断：执行目标和实际角都为 `0.25 rad`，但关节仍向角度增大的方向转动；在 `kd>0` 的这段代码里，总 PD 力矩一定为零吗？请指出会参与计算的那一项。本人尚未回答，不预记为答对。阻尼与控制先后顺序记为“已讲解／仍需确认”，本题算对不替代完整控制链的独立操作验收。
