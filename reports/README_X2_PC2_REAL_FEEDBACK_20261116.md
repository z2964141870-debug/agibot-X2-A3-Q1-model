# X2 PC2 本地策略和真实反馈只读联跑

## Done

在 Orin 以记录的到达节拍向 PC2 单向发送 300 个保存 HumanFrame。PC2 用 ROS 2 订阅真实腿、腰、臂、头和躯干 IMU，读取本体反馈，在本地用两线程 MorphMimic 计算建议角度。策略向本地文件写目标，不将动作回发 Orin。使用临时开发网监听，仅允许 Orin。隔离复制的 AimDK 反馈消息包在 PC2 成功加载 ROS 类型支持。现场控制后端和发布者均未启动。既有躯干外参配置来自现有工程，`measured_sensor_calibration=false`。

| PC2 试测 | 结果 |
| --- | ---: |
| 发送 / 收到的人体包 | 300 / 300 |
| 人体包到达间隔 P95 / 最大 | 45.68 / 72.32 ms |
| 真实反馈最大分组接收年龄 P95 / 最大 | 6.18 / 9.97 ms |
| PC2 就绪策略目标 | 131 |
| 首到末个就绪目标的有效频率 | 13.10 Hz |
| 本地完整就绪处理周期中位 / P95 | 60.34 / 98.65 ms |
| 本地完整就绪处理周期超过 20 ms | 127 / 131 |
| 跳过的计划周期 | 367 |

10 个周期等待首次完整人体窗，输入结束后 11 个周期按新鲜度拒绝。只有 1 对目标相邻两个计划周期都就绪，该对的最大关节差为 4.61°，样本不足以判断动作连续性。反馈年龄是接收时间代理，未从跨板原始时钟算单向采集延迟。空跑两线程 ONNX 的 15.54 ms P95 只代表前向；本轮增加了真实反馈、逆运动学相关的传感转换、人体参考窗和特征构建，现有计时仍不能把 98.65 ms 分到某个算子或系统负载。本轮没有实时 FGP 推理、没有启动 MC 交接或电机发布。

结论是该拓扑的数据和真反馈链路可以工作，但这份 PC2 本地运行时只交付约 13 Hz 的建议目标，不能替代现有 Orin 策略与后端。优先保持 Orin 为现场候选。PC2 若继续承担推理，先用低开销分段计时对齐取窗、特征、前向和 ROS 回调，再决定是否值得移植原生 C++ 路径。
