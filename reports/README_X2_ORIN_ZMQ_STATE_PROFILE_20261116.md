# X2 Orin 状态请求分段计时

## Done

用同一板端录制，在共享、分离、分离、共享 REP 四轮 TCP 回环中各释放 359 个人体请求和 600 个状态请求。状态使用固定合成反馈，策略使用原 CPU ONNX。每轮 589 个状态就绪。逐次核对客户端发送到收到回复的总时长，精确拆为服务收到前、解码、取窗锁等待、取窗构建、ONNX、其余运行时、回包编码和回传八段。没有改变状态机或发送电机命令。板端结果已与 Mac 按 SHA-256 核同，源码在独立临时目录，原结果与现行入口保留。

| 指标，两轮分别列出 | 共享 REP | 人体独立 REP |
| --- | ---: | ---: |
| 人体包 RPC P95 | 9.33 / 9.58 ms | 4.79 / 2.80 ms |
| 状态 RPC P95 | 13.97 / 13.35 ms | 14.32 / 12.86 ms |
| 就绪状态超过 20 ms | 4 / 1178 | 4 / 1178 |
| 取窗锁等待 P95 | 0.008 / 0.006 ms | 0.006 / 0.006 ms |
| 取窗构建 P95 | 2.18 / 2.19 ms | 2.11 / 2.14 ms |
| ONNX 前向 P95 | 7.03 / 6.31 ms | 6.49 / 5.09 ms |

以各轮就绪样本中位数为参照，8 个超时中最大增加项为 ONNX 4 个、其余运行时 3 个、回包后等待 1 个。两个 ONNX 慢例耗时均约 14.4 ms，但调用线程 CPU 分别为 14.34 ms 和 4.01 ms，现有计时不能区分其等待落在 ORT 线程池、系统调度或其他同步点。最慢的共享 REP 状态请求 32.78 ms，回包后 10.81 ms、其余运行时 10.61 ms、取窗构建 6.27 ms。该结果不能代替上一轮未分段的 29.55 ms 样本归因。

两组配对 589 个共同就绪周期，参考槽时间和支持都相同的为 577 与 583。较长录制中，所有轮最大连续关节目标步长约 24.14–30.18°。独立接口提前了人体确认，动作连续性和状态期限仍需要独立验收。

板端 FGP 的历史联合录制跑到平均 29.984 Hz、900 输出零跳过，但确认间隔 P95 43.38 ms；这与真人联测 21.6 Hz 和推理尖峰属于不同条件。当前保留板端 FGP 为候选，优先看实时输入下的出帧分位数、状态超时以及长间隔恢复，未恢复真机控制。
